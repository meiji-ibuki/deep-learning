38.1 効率化の指標とボトルネック

第37章のアンサンブルは精度を改善できる一方、学習・推論コストを増やす。本章では精度を維持しながら計算資源を節約する方法を学ぶ。レイテンシは一要求の完了時間、スループットは単位時間に処理する標本数である。バッチサイズB、バッチ処理時間t秒ならスループットはB/tである。バッチを大きくしても個々の要求の待ち時間が短くなるとは限らない。

$$S=\frac{t_{\rm baseline}}{t_{\rm optimized}},\qquad \eta=\frac{S}{N}$$

後者は同じ仕事量を1台で処理した時間を基準に、同種のN台へ並列化した場合の効率。精度・時間・ピークメモリ・モデル容量・消費電力を同じ条件で比較する。FLOPs（浮動小数点演算数）とFLOP/s（毎秒演算数）は別物であり、積和を2演算と数えるかも明記する。

元の処理時間の割合p（0〜1）をk倍（k≥1）高速化し、残りの処理時間は変わらず追加オーバーヘッドがない場合、Amdahlの法則より全体の高速化は $1/((1-p)+p/k)$。入出力が支配的なら演算だけを高速化しても限界がある。

38.2 GPUとメモリの基礎

CPUは複雑な制御に、GPUは多数の同型演算の並列処理に適する。行列積や畳み込みではGPUを活用しやすい。ただし小さな演算ではカーネル起動やCPU–GPU間の転送が支配的になり得る。Tensor Coreなどの専用演算器を使えるかは型・形状・ハードウェアに依存する。

メモリは重みだけではない。P個のFP32パラメータにAdamを適用する単純な見積りは、重み・勾配・一次モーメント・二次モーメントの計16Pバイト。例えば1000万パラメータなら160MB（十進単位）。さらに活性化値、一時バッファ、アロケータの予約領域が必要である。活性化値は概ねバッチサイズに比例する。

演算強度Iを演算数/転送バイトとすると、Rooflineの上限は $\min(C,WI)$（Cはピーク演算速度、Wはメモリ帯域）。理論上限であり実測性能ではない。

コード38.1　GPUの確認とメモリ設定
import tensorflow as tf
# GPU初期化より前に設定する
for gpu in tf.config.list_physical_devices('GPU'):
    tf.config.experimental.set_memory_growth(gpu, True)
print(tf.config.list_physical_devices('GPU'))

38.3 入力パイプラインの最適化

tf.dataでは読み込み・デコード・前処理・バッチ化を組み合わせる。parallel mapとprefetchを使い、CPUの前処理とGPUの学習を重ねる。cacheは決定的で高価な処理の後、ランダム拡張やshuffleの前に置くと各epochの変化を保ちやすい。キャッシュを確定するには入力データセットを最後まで走査する必要がある。大規模データはRAMに収まるか確認し、必要に応じてディスクキャッシュを使用する。

前処理が4ms、学習が6msの仮想バッチなら逐次処理は10ms、理想的な重複処理の定常状態は6ms/バッチである。最初と最後の待ち時間は残る。prefetchは無限に高速化するわけではない。

コード38.2　入力パイプライン（人工画像）
import numpy as np
import tensorflow as tf
rng=np.random.default_rng(38)
x=rng.integers(0,256,(1024,32,32,3),dtype=np.uint8)
y=rng.integers(0,10,1024,dtype=np.int32)
ds=tf.data.Dataset.from_tensor_slices((x,y))
ds=ds.map(lambda a,b:(tf.cast(a,tf.float32)/255.,b),num_parallel_calls=tf.data.AUTOTUNE)
ds=ds.cache().shuffle(1024,seed=38).batch(64).prefetch(tf.data.AUTOTUNE)

38.4 Mixed Precision

Mixed Precisionは演算の多くをFP16またはBF16で行い、重みなどをFP32で保持する手法である。FP16は指数5ビット・仮数部10ビット、BF16は指数8ビット・仮数部7ビット、FP32は指数8ビット・仮数部23ビット（いずれも符号1ビット）。BF16はFP32に近い指数範囲を持つが精度は粗い。FP16では小さな勾配がゼロに丸められるため、損失をS倍して微分し、更新前に勾配をSで割るLoss Scalingを利用する。

$$\nabla_\theta (SL)=S\nabla_\theta L$$

動的Loss Scalingは非有限勾配が出た更新をスキップしスケールを調整する。Kerasのmixed_float16とModel.fitでは通常自動で扱われる。出力logitや損失計算はFP32にする。mixed_bfloat16では一般にLoss Scalingは不要。高速化率はデバイス依存であり、必ず同じ精度・条件で測定する。

コード38.3　FP16のアンダーフローを確認
import numpy as np
g=np.array([1e-3,1e-5,1e-7,1e-9],dtype=np.float32)
S=1024
raw=g.astype(np.float16).astype(np.float32)
scaled=(g*S).astype(np.float16).astype(np.float32)/S
print(np.c_[g,raw,scaled])
assert raw[-1]==0 and scaled[-1]>0
コード38.4　Mixed Precisionの学習例（コード38.2の後に実行）
from tensorflow import keras
keras.mixed_precision.set_global_policy('mixed_float16')
model=keras.Sequential([keras.Input((32,32,3)),keras.layers.Conv2D(32,3,activation='relu'),keras.layers.GlobalAveragePooling2D(),keras.layers.Dense(10,dtype='float32')])
model.compile(optimizer='adam',loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),metrics=['accuracy'])
model.fit(ds,epochs=2)
keras.mixed_precision.set_global_policy('float32') # 既存層の型は変わらない

38.5 tf.functionとXLA

tf.functionはPython関数をグラフとして実行し、Pythonによる逐次ディスパッチを減らす。入力形状やPython引数が変わると再トレースが発生する場合がある。input_signatureで形状を制約することが有効である。XLAは演算融合やバッファ最適化を行うコンパイラで、jit_compile=Trueで明示的に要求できる。未対応演算はエラーになることがある。初回コンパイル時間は定常実行時間と分けて記録する。

コード38.5　グラフ化・XLAと計測
import time
import tensorflow as tf
@tf.function(input_signature=[tf.TensorSpec([256,256],tf.float32)],jit_compile=True)
def fused(x):
    return tf.reduce_sum(tf.nn.relu(x*x+1))
x=tf.random.normal((256,256))
t=time.perf_counter(); fused(x).numpy(); print('first',time.perf_counter()-t)
t=time.perf_counter()
for _ in range(50): fused(x).numpy() # ホストへ結果を取得して完了を待つ
print('steady seconds/call',(time.perf_counter()-t)/50)

38.6 分散学習

データ並列では各GPUが異なるミニバッチを処理し、勾配を集約して同じ重みを更新する。各レプリカが同数bの標本を処理する場合、グローバルバッチはB=Nb、平均勾配は $g=N^{-1}\sum_{r=1}^{N}g_r$。All-reduce通信のコストが増えるためGPU数と速度は比例しない。モデル並列は重みや層を分割し、単一GPUに収まらないモデルに対応する。パイプライン並列は複数の段階で計算を重ねる。

バッチサイズが変われば最適化の性質も変わる。学習率の線形スケーリングは経験則であり、Warmupと併せても検証が必要。Kerasのfitを使えば分散時の損失集約を任せられる。

コード38.6　MirroredStrategyによる学習
import tensorflow as tf
from tensorflow import keras
strategy=tf.distribute.MirroredStrategy()
print('replicas:',strategy.num_replicas_in_sync)
with strategy.scope():
    m=keras.Sequential([keras.Input((32,32,3)),keras.layers.Conv2D(16,3,activation='relu'),keras.layers.GlobalAveragePooling2D(),keras.layers.Dense(10)])
    m.compile(optimizer='adam',loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True))
# 人工データを新規生成。global batchは64×レプリカ数
batch=64*strategy.num_replicas_in_sync
import numpy as np
rng=np.random.default_rng(38)
x_images=rng.random((1024,32,32,3),dtype=np.float32)
y_labels=rng.integers(0,10,1024,dtype=np.int32)
train=tf.data.Dataset.from_tensor_slices((x_images,y_labels)).batch(batch,drop_remainder=True).prefetch(tf.data.AUTOTUNE)
m.fit(train,epochs=2)

38.7 勾配累積とメモリ節約

勾配累積は小さなマイクロバッチを複数回処理し、一度の更新にまとめる。同一の重みで各標本の損失を平均し、標本間で結合した演算がない場合、異なるサイズb_iの勾配g_iは $g=\sum_i b_i g_i/\sum_i b_i$ とする。同サイズK回なら平均でよい。更新頻度と学習率スケジュールは実効バッチを基準に設計する。Batch Normalizationの統計、Dropout、乱数、勾配クリッピングのタイミングにより巨大バッチと完全一致しない場合がある。活性化チェックポイント（再計算）は順伝播の中間値を一部破棄し逆伝播時に再計算してメモリを節約する。

コード38.7　勾配累積の等価性（線形回帰）
import numpy as np
rng=np.random.default_rng(38)
X=rng.normal(size=(23,4)); y=rng.normal(size=23); w=rng.normal(size=4)
full=2*X.T@(X@w-y)/len(X)
acc=np.zeros_like(w)
for ids in np.array_split(np.arange(len(X)),4):
    acc+=2*X[ids].T@(X[ids]@w-y[ids])/len(X)
print(np.max(np.abs(full-acc)))
assert np.allclose(full,acc)

38.8 量子化の原理と数値実験

量子化では実数rを整数qに近似する。スケールsとゼロ点zを用いるアフィン量子化は

$$q=\operatorname{clip}(\operatorname{round}(r/s)+z,q_{min},q_{max}),\qquad \hat r=s(q-z)$$

対称INT8の例ではz=0、s=max|r|/127（全要素が0なら任意の正のスケールを使う）、整数範囲−127〜127を利用する。範囲内の丸め誤差は最大s/2（浮動小数点誤差を除く）。外れ値がスケールを広げると小さな重みの精度が悪化する。チャネル別量子化はこの問題を緩和できる。FP32からINT8なら重みの生データ容量は1/4だが、実ファイルにはメタデータ等が含まれる。

PTQは学習後変換、QATは学習中に量子化誤差を模擬する方法。動的範囲量子化は重みを中心に変換し、完全整数量子化は代表データで活性化範囲を較正する。実行時の演算対応や精度劣化を確認する。

コード38.8　対称INT8の数値実験
import numpy as np
rng=np.random.default_rng(38)
w=rng.normal(0,.2,(256,128)).astype(np.float32)
s=float(np.max(np.abs(w)))/127
if s == 0:
    s = 1.0
q=np.clip(np.rint(w/s),-127,127).astype(np.int8)
wq=q.astype(np.float32)*s
print('bytes',w.nbytes,q.nbytes,'max error',np.max(np.abs(w-wq)))
assert np.max(np.abs(w-wq))<=s/2+1e-7
inputs=rng.normal(size=(128,256)).astype(np.float32)
a=inputs@w; b=inputs@wq
print('relative output error',np.linalg.norm(a-b)/np.linalg.norm(a))

38.9 枝刈り・蒸留・モデル設計

枝刈り（pruning）は重要度の低い重みやチャネルを除去する。非構造化枝刈りでは個々の重みをゼロ化し、疎行列に適した演算器がなければ速度向上は保証されない。構造化枝刈りはチャネルやヘッドなどを除去して密なテンソルの形状を縮小する。再学習して精度を回復させることがある。第37章の知識蒸留は小型モデルへ教師の予測を転移する別の方法である。

最初からMobileNetなどの効率的なアーキテクチャを選ぶ、入力解像度を下げる、推論時のTTAやアンサンブル数を減らすという選択肢もある。精度とレイテンシのPareto前線（他候補によって両指標で同等以上、かつ少なくとも一方で厳密に上回られることのない構成）を比較する。

38.10 実践：推論ベンチマークとモデル変換

実習ではMNISTを用い、FP32モデルと動的範囲量子化したLiteRTモデルのサイズ・精度・レイテンシを比較する。コード38.9と38.10は連続実行する。TensorFlow同梱のtf.lite APIを利用するが、環境によって独立のLiteRTランタイムへ移行が必要になる。訓練時の設定は固定し、テストは評価専用とする。CPU上の同一ランタイム、同じ入力、同じスレッド数で測定する。初期化・ウォームアップ・定常計測を分離する。

コード38.9　MNIST学習とLiteRTへの変換
import tensorflow as tf
from tensorflow import keras
import numpy as np
keras.utils.set_random_seed(38)
keras.mixed_precision.set_global_policy('float32')
(xtr,ytr),(xte,yte)=keras.datasets.mnist.load_data()
xtr=xtr.reshape(-1,784).astype('float32')/255
xte=xte.reshape(-1,784).astype('float32')/255
m=keras.Sequential([keras.Input((784,)),keras.layers.Dense(128,activation='relu'),keras.layers.Dense(10)])
m.compile(optimizer='adam',loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True))
m.fit(xtr,ytr,batch_size=128,epochs=5,verbose=0)
def convert(quantize):
    c=tf.lite.TFLiteConverter.from_keras_model(m)
    if quantize: c.optimizations=[tf.lite.Optimize.DEFAULT]
    return c.convert()
models={'float':convert(False),'dynamic':convert(True)}
print({k:len(v) for k,v in models.items()})
コード38.10　同一条件の推論ベンチマーク
import time
for name,content in models.items():
    interpreter=tf.lite.Interpreter(model_content=content,num_threads=1)
    interpreter.allocate_tensors()
    inp=interpreter.get_input_details()[0]['index']
    out=interpreter.get_output_details()[0]['index']
    def predict(row):
        interpreter.set_tensor(inp,row[None,:])
        interpreter.invoke()
        return interpreter.get_tensor(out).argmax()
    for row in xte[:30]: predict(row)
    times=[]; pred=[]
    for row in xte:
        t=time.perf_counter(); pred.append(predict(row)); times.append(time.perf_counter()-t)
    print(name,'accuracy',np.mean(np.array(pred)==yte),
          'median ms',1000*np.median(times),'p95 ms',1000*np.quantile(times,.95))

38.11 Kaggleでの計算予算管理

プロファイラで入力待ち、演算、転送、通信の割合を特定し、一つずつ変更する。KaggleではGPU時間とストレージ制限、提出時の実行時間を事前に確認する。具体的な上限はコンペや環境によって異なる。学習時間だけでなく、データ準備・全Foldの推論・出力保存まで含めて予算を立てる。TensorBoard Profilerではホストとデバイスのタイムラインを分析できる。プロファイル自体の負荷があるので短区間で取得し、通常時の計測と区別する。

ベースライン→入力改善→混合精度→XLA→バッチ調整→モデル縮小の順は一例であり、実測で支配的な要因から対応する。精度と速度を同じ分割で比較し、環境・ライブラリ版・シード・バッチ・ウォームアップ回数を記録する。

38.12 まとめと確認問題

高速化の第一歩は計測である。演算型、メモリ、入力、通信、モデル構造のどこが制約かを理解したうえで最適化を選ぶ。次章ではこれらをコンペティションのワークフローに統合する。

問1　バッチ64を8msで処理するスループットは？

8000標本/秒。

問2　処理時間の80%を4倍速にした全体の高速化率は？

1/(0.2+0.8/4)=2.5倍。

問3　1000万個のFP32重みの生容量は？

40MB（十進単位）。

問4　Loss Scalingの目的は？

小さな勾配のアンダーフローを抑える。

問5　XLAの初回時間を分離する理由は？

コンパイル負荷と定常実行時間を区別するため。

問6　4GPUで局所バッチ32ならグローバルバッチは？

128。

問7　勾配累積と巨大バッチが異なる理由は？

BN統計、乱数、更新タイミングなど。

問8　非構造化枝刈りで必ず高速化するか？

しない。疎演算への対応が必要。

問9　発展：量子化前後を比較せよ。

コード38.9〜38.10を使い、許容するAccuracy低下幅（例：1ポイント）を事前に定める。同じテストデータ・CPU・ランタイム・スレッド数・バッチサイズで精度、ファイル容量、ウォームアップ後の中央値とp95を記録する。容量比と速度比はFP32版を基準に計算する。設定の選択には別の検証集合を使い、最終テストは選択後に行う。

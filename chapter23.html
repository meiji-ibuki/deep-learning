第23章　学習状況の分析とデバッグ

学習の失敗を観測し、原因を切り分ける

本章は学習技術編の総仕上げである。学習曲線やテンソルの状態から異常を診断し、再現可能な実験で修正を検証する。

この章の到達目標

  • データ・損失・勾配・更新を段階的に検査できる。
  • TensorBoardと比較実験を活用できる。

23.1　デバッグの考え方と診断の順序

学習が進まないとき、モデルの層数を増やす前に、データ・目的関数・計算・評価のどこに問題があるかを切り分ける。デバッグとは仮説を立て、観測可能な量を選び、一つの変更で仮説を検証する作業である。第15章の学習履歴、第17章のカスタム学習、第19章の分布監視、第22章の検証設計を統合する。

23.2　学習曲線から読み取れる症状

訓練損失と検証損失を同じ軸で描く。訓練・検証の差は過学習の手がかりだが、データ分布の違いや訓練時だけ有効なDropout・データ拡張でも差が生じる。学習曲線だけで原因を断定しない。検証値はエポック末のモデル、訓練値は更新中のモデルの集計という違いにも注意する。

症状考えられる原因最初の検証
両方高い学習不足・表現力不足・前処理不良少数標本への過適合
訓練のみ低い過学習・分布差分割と正則化を確認
急増・振動学習率過大・異常値学習率を下げ有限性を検査
検証だけ極端に良いリーク・評価条件の差重複・前処理・推論モード確認
損失低下・指標停滞閾値・指標設定の不整合確率と混同行列を確認

23.3　データとラベルを最初に検査する

数値特徴量の範囲、欠損率、ラベル頻度、IDの重複、分割間の重なりを確認する。予測が (B,1)、ラベルが (B,) のまま独自の二乗誤差を計算すると、意図せず (B,B) になる。分類ではラベルの整数範囲と出力次元、from_logits の設定も確認する。画像や文章は変換後の標本を実際に可視化し、ラベルと対応するか確認する。

コード23.1　二値分類データの検査
import numpy as np

def check_binary(X, y):
    X, y = np.asarray(X), np.asarray(y)
    assert X.ndim == 2 and y.shape == (len(X), 1)
    assert len(X) > 0 and X.dtype.kind in 'fiu'
    assert np.isfinite(X).all() and np.isfinite(y).all()
    assert np.isin(y, [0, 1]).all()
    print('shape:', X.shape, y.shape)
    print('feature range:', X.min(0), X.max(0))
    print('positive rate:', y.mean())

check_binary(np.array([[1., 2.], [3., 4.]]), np.array([[0], [1]]))

欠損を許容する生データでは欠損率を記録し、補完後のモデル入力に対して有限性検査を行う。IDの重複はタスクによって正常な場合もあるため、患者・ユーザー・時系列などのグループ単位を確認する。

23.4　ベースラインと少数標本への過適合テスト

回帰ならMSEに対して訓練平均、MAEに対して訓練中央値を、分類なら交差エントロピーに対して訓練クラス比率などの定数予測を基準とする。Accuracyなら最頻クラスを基準にする。次に32標本程度を固定して、十分な容量のモデルが訓練損失を下げられるか試す。これは汎化性能の評価ではなく、学習経路の健全性確認である。矛盾ラベルや強い正則化がある場合、完全な適合は期待できない。

コード23.2　固定ミニバッチの過適合テスト（TensorFlow）
import tensorflow as tf
from tensorflow import keras
import numpy as np
keras.utils.set_random_seed(23)
rng = np.random.default_rng(23)
X = rng.normal(size=(32, 4)).astype('float32')
y = (X[:, :1] ** 2 + X[:, 1:2]).astype('float32')
model = keras.Sequential([keras.Input((4,)),
    keras.layers.Dense(64, activation='relu'),
    keras.layers.Dense(64, activation='relu'), keras.layers.Dense(1)])
model.compile(optimizer=keras.optimizers.Adam(0.01), loss='mse')
h = model.fit(X, y, epochs=300, batch_size=32, shuffle=False, verbose=0)
print('first/last:', h.history['loss'][0], h.history['loss'][-1])
print('baseline:', np.mean((y - y.mean()) ** 2))

23.5　NaN・Infと数値安定性

NaNは未定義演算、Infは無限大を表す。指数のオーバーフロー、ゼロ除算、負数の対数、過大な更新が典型的な原因である。最初に非有限値が生じた演算を特定する。単純な欠損置換で症状を隠してはいけない。

二値交差エントロピーをロジットから安定に計算する式は第10章のとおりである。

$$\ell(z,y)=\max(z,0)-zy+\log(1+e^{-|z|})$$
コード23.3　不安定な計算と安定な計算の比較
import numpy as np
z = np.array([-1000., 0., 1000.])
y = np.array([1., 1., 0.])
with np.errstate(over='ignore', divide='ignore', invalid='ignore'):
    p = 1 / (1 + np.exp(-z))
    naive = -y*np.log(p) - (1-y)*np.log1p(-p)
stable = np.maximum(z, 0) - z*y + np.log1p(np.exp(-np.abs(z)))
print(naive, stable)
assert np.isfinite(stable).all()

TensorFlowでは tf.debugging.assert_all_finite で要所を検査する。tf.debugging.enable_check_numerics() は演算単位の調査に役立つが、オーバーヘッドがあるため調査後に無効化する。混合精度では損失スケーリングやfloat32での損失計算も重要となる（第38章）。

23.6　勾配・重み・更新量を監視する

重みや勾配テンソルを平坦化したユークリッドノルム（行列ならFrobeniusノルム）を用いる。層ごとの勾配ノルム $\|g_l\|_2$ と重みノルム $\|W_l\|_2$ を観測する。更新量の相対尺度 $r_l=\|W_l^{new}-W_l^{old}\|_2/(\|W_l^{old}\|_2+\epsilon)$ は、勾配だけでは分からない実際の更新の大きさを示す。Adamなどでは勾配ノルムと更新量は単純比例しない。普遍的な正常閾値はないので層間・時間方向・実験間で比較する。

コード23.4　1バッチの勾配と更新を検査する（前節までのmodelとは独立）
import tensorflow as tf
from tensorflow import keras
keras.utils.set_random_seed(23)
m = keras.Sequential([keras.Input((4,)), keras.layers.Dense(8, activation='relu'), keras.layers.Dense(1)])
opt = keras.optimizers.Adam(0.001)
x = tf.ones((8, 4)); y = tf.zeros((8, 1))
with tf.GradientTape() as tape:
    pred = m(x, training=True)
    loss = tf.reduce_mean(tf.square(pred-y))
tf.debugging.assert_all_finite(loss, 'loss')
vs = m.trainable_variables
gs = tape.gradient(loss, vs)
old = [tf.identity(v) for v in vs]
for v, g in zip(vs, gs):
    if g is None:
        raise ValueError(f'Unconnected variable: {v.name}')
    tf.debugging.assert_all_finite(g, v.name)
opt.apply_gradients(zip(gs, vs))
for v, g, before in zip(vs, gs, old):
    ratio = tf.norm(v-before)/(tf.norm(before)+1e-8)
    print(getattr(v, 'path', v.name), float(tf.norm(g)), float(ratio))

Noneは既定の設定で微分可能な経路がない場合や微分対象が監視されていない場合などに返り、数値としてのゼロ勾配とは異なる。NumPyへ変換した演算、stop_gradient、Tapeの外での演算、整数型の微分対象などを確認する。意図的に凍結された変数は学習対象から除く。勾配クリッピングは発散を抑える対策であり、誤ったラベルや損失の修正にはならない。

23.7　活性化値と勾配の分布を調べる

平均・標準偏差・ゼロ率・有限値率を層ごとに記録する。ReLUのゼロ率が高いだけではDying ReLUと断定できない。全標本で長期間ゼロとなるユニットを確認する。Sigmoidでは飽和領域の割合も有用である。

コード23.5　深い線形ネットワークの信号伝播実験
import numpy as np
rng = np.random.default_rng(23)
B, D, L = 128, 64, 30
X = rng.normal(size=(B, D))
base = [rng.normal(size=(D, D))/np.sqrt(D) for _ in range(L)]
g0 = rng.normal(size=(B, D))
results = {}
for scale in [0.5, 1., 1.5]:
    W = [scale*w for w in base]
    a = X.copy(); forward = [np.std(a)]
    for w in W:
        a = a @ w
        forward.append(np.std(a))
    g = g0.copy(); backward = [np.std(g)]
    for w in reversed(W):
        g = g @ w.T
        backward.append(np.std(g))
    results[scale] = (forward, backward)
    print(scale, forward[-1], backward[-1])

この実験は活性化関数や学習を省略して信号の伝播だけを分離したもの。実際のモデルでは非線形性、残差接続、正規化、損失関数も影響する。第19章の初期化の議論と対応させて読む。

23.8　TensorBoardによる学習の可視化

TensorBoardでは学習履歴を時系列で比較できる。スカラー、ヒストグラム、プロファイルなどを用い、実験ごとにログディレクトリを分離する。重みのヒストグラムを記録するだけでは勾配が記録されるとは限らない。必要ならカスタム学習ステップで明示的に書き出す。

コード23.6　TensorBoardを利用する最小例
import tensorflow as tf
from tensorflow import keras
from datetime import datetime
from pathlib import Path
import numpy as np
keras.utils.set_random_seed(23)
x = np.linspace(-2, 2, 128, dtype='float32')[:, None]
y = np.sin(x)
m = keras.Sequential([keras.Input((1,)), keras.layers.Dense(16, activation='tanh'), keras.layers.Dense(1)])
m.compile(optimizer='adam', loss='mse')
logdir = Path('logs/ch23') / datetime.now().strftime('%Y%m%d-%H%M%S-%f')
cb = keras.callbacks.TensorBoard(log_dir=str(logdir), histogram_freq=1)
m.fit(x[:96], y[:96], validation_data=(x[96:], y[96:]), epochs=10, callbacks=[cb], verbose=0)

端末で tensorboard --logdir logs/ch23 を実行し、表示されたローカルURLをブラウザで開く。Notebook環境では %load_ext tensorboard と %tensorboard --logdir logs/ch23 が利用できる場合がある。上の分割はログ出力の動作例であり、外挿領域を検証する設定である。

23.9　再現可能な実験と性能の切り分け

乱数シード、データ分割ID、前処理、モデル設定、学習率、ライブラリ版、デバイスを保存する。決定論的演算を有効にしても異なるハードウェアやバージョン間の完全一致は保証されない。性能が落ちた場合、直前の正常な実験を再現し、差分を一つずつ戻す。GPU利用率の低さは入力パイプラインが原因のこともあるため、第16章のprefetchとプロファイラを確認する。

記録項目目的
seed・分割IDデータ条件の再現
設定・コードの版変更点の特定
loss・metric・学習率学習挙動の比較
勾配・更新量・有限値率計算異常の切り分け
処理時間・デバイス計算ボトルネックの特定

23.10　実践：学習率の異常を診断する

NumPyによる線形回帰で、学習率だけを変える実験を行う。入力のスケールは損失曲面の曲率に影響する。第18章の収束条件に照らし、学習率の変更と標準化という二つの仮説を分けて検証する。

コード23.7　学習率と標準化の比較実験
import numpy as np
rng = np.random.default_rng(23)
X = rng.normal(size=(256, 2))*np.array([1., 10.])
y = X @ np.array([2., .3]) + rng.normal(0, .1, 256)
Z = (X-X.mean(0))/X.std(0)
curves = {}
for name, A, lr in [('raw_small', X, .005), ('raw_large', X, .02), ('scaled_large', Z, .02)]:
    w = np.zeros(2); b = 0.; losses = []
    for t in range(80):
        e = A @ w+b-y
        losses.append(np.mean(e**2))
        w -= lr*(2*A.T@e/len(A)); b -= lr*2*e.mean()
    curves[name] = losses
    print(name, losses[0], losses[-1])

raw_largeの発散を観測したら、まずraw_smallと比較して学習率の影響を確認する。scaled_largeは同じ学習率でも入力の尺度を変えた結果である。この実験は訓練挙動の診断であり、未知データへの評価ではない。実務では標準化の統計量は訓練データのみで推定する。

23.11　まとめと確認問題

原因を推測するだけでなく、最小の実験で反証できる仮説へ変換することが重要である。データ、順伝播、損失、勾配、更新、評価という順序を守ると、複雑なモデルでも問題を局所化できる。

問1　訓練損失と検証損失がともに高いとき、何を確認するか。

ラベルや前処理、ベースライン、固定少数標本への適合を確認する。

問2　None勾配とゼロ勾配の違いは何か。

Noneは既定設定で微分可能な経路がない場合などに返る。ゼロは計算された勾配の値が0であることを示す（寄与の相殺でも生じる）。

問3　NaNが生じたとき最初に行うことは何か。

最初に非有限値が現れる入力・演算・勾配・更新を特定する。

問4　訓練損失より検証損失が低いことは必ずリークか。

いいえ。Dropoutや拡張、集計時点、分布差なども原因となり得る。

問5　重みのノルムだけで学習の健全性を判断できるか。

できない。更新量、勾配、活性化値、損失なども比較する。

問6　固定少数標本への過適合テストの目的は何か。

学習経路が正常に動くか確認する。汎化評価ではない。

問7　TensorBoardのログを実験ごとに分ける理由は何か。

条件の異なる結果が混在するのを防ぎ比較可能にする。

問8　複数シードで比較する理由は何か。

偶然の初期値やシャッフルによる差を評価するため。

問9　発展：実践コードの学習率を0.001〜0.03で変え、収束境界を推定せよ。

切片を含む設計行列Hを作り、MSEのヘッセ行列2H.T@H/Nの最大固有値λから安定条件0<η<2/λを求める。正定値のヘッセ行列を持つ二次損失で固定学習率の全バッチ勾配降下法を使う場合の条件である。初期値の方向や有限回の観測によって見かけの境界は変わり得る。コード23.7の生入力では最大固有値201.96522337、理論上限0.009902695（独立再計算）。

29.1 表形式データと問題設定

表形式データ（tabular data）は行が標本、列が特徴量を表す。住宅価格なら面積・築年数・地域から価格を推定する回帰、顧客離脱なら契約情報から離脱確率を推定する分類となる。画像や系列と違って列ごとに意味・単位・分布が異なり、列の隣接関係に一般的な意味はない。このためCNNを無条件に適用するのではなく、まずMLPやツリーベースモデルを検討する。

最初に予測時点、予測対象、利用可能な特徴量、評価指標を定義する。例えば契約終了後に記録された解約理由は離脱予測時には利用できない。IDは結合や提出に必要だが、予測に使う根拠がなければ除外する。

列例処理
数値面積・築年数補完・標準化
名義カテゴリ地域・商品種別One-hot / Embedding
順序カテゴリ評価A〜C順序を明示
日時契約日曜日・経過日数
目的変数価格・離脱特徴量から分離

29.2 データの検査と検証設計

学習前に列の型、欠損率、重複、カテゴリ数、目的変数の分布を確認する。分割方法は実運用で未知となる単位に合わせる。未知の顧客への汎化を評価し、同一顧客の複数行があるならGroupKFold、未来を予測するなら時間順分割、独立した分類標本ならStratifiedKFoldを候補とする。時系列では予測時点より後の情報が特徴量に含まれないこと、および訓練ラベルの確定時点が検証の予測時点より後にならないことも確認する。

交差検証では各Foldで前処理をfitする。外側の検証FoldをEarlyStoppingに使うと、そのFoldのラベルがモデル選択に関与する。本章の実践では外側訓練部分をさらに内側訓練・内側検証に分ける。

29.3 数値特徴量と特徴量エンジニアリング

MLPでは特徴量の尺度が勾配の大きさに影響する。訓練データから中央値・平均・標準偏差を推定し、検証・テストに同じ変換を適用する。欠損フラグを追加すると、欠損そのものが情報を持つ場合に利用できる。定数列では標準偏差0を避ける。

$$z_j=(x_j-\mu_j)/\sigma_j$$

面積×単価のような積、比率、対数、周期変換はドメイン知識を明示する。曜日を数値として使うと日曜と月曜が遠くなるため、周期Pに対してsin・cosに変換できる。

$$u=\sin(2\pi t/P),\qquad v=\cos(2\pi t/P)$$

比率の分母0、log1pの定義域、未来の情報を含む集計に注意する。特徴量の採否は検証で判断する。

コード29.2　行単位の特徴量生成
import numpy as np
import pandas as pd

def make_features(df):
    out = df.copy()
    out["area_per_room"] = out["area"] / out["rooms"].replace(0, np.nan)
    out["log_area"] = np.log1p(out["area"].where(out["area"] >= 0))
    date = pd.to_datetime(out["date"], errors="coerce")
    out["weekday_sin"] = np.sin(2*np.pi*date.dt.dayofweek/7)
    out["weekday_cos"] = np.cos(2*np.pi*date.dt.dayofweek/7)
    return out.drop(columns="date")

29.4 カテゴリ変数の表現とEmbedding

One-hotは低カーディナリティのカテゴリに適する。高カーディナリティでは語彙数Vと埋め込み幅dの行列Eを学習するEmbeddingが候補となる。カテゴリID kの表現はEのk行目である。IDをそのまま連続値にする方法とは異なり、大小関係を仮定しない。

$$e_k=E_{k,:},\quad E\in\mathbb R^{V\times d}$$

未知カテゴリ用のOOVを確保し、欠損は専用文字列に変換する。語彙は訓練部分から作り、検証・テストでは固定する。頻度エンコーディングも訓練部分から計算する。Target Encodingは目的変数を使うため、訓練行自身のラベルを含まないOOF変換が必要である。分類では平滑化したカテゴリ平均を用いることがある。

$$TE(c)=\frac{\sum_{i:x_i=c} y_i+\alpha\bar y}{n_c+\alpha}$$

この式の集計対象は変換対象の行を含まない訓練部分とする。未知カテゴリは訓練平均に戻す。平滑化係数は正とし、全体平均も各変換用の訓練部分だけで求める。

29.5 Tabular MLPの設計

数値特徴量は標準化し、カテゴリはEmbeddingへ入力する。両者を結合したベクトルにDense・ReLU・Dropoutを適用する。幅や深さを増やす前に小さな基準モデルを作り、過学習を確認する。例えば数値3列、語彙8・埋め込み幅4なら結合幅7、Dense(32)のパラメータは(7+1)×32=256、Embeddingは32個である。

コード29.3　回帰・分類で共通のモデル構築
import tensorflow as tf
from tensorflow import keras

def build_model(n_num, vocab_size, task="regression"):
    num = keras.Input((n_num,), name="num")
    cat = keras.Input((1,), dtype="int32", name="cat")
    e = keras.layers.Embedding(vocab_size, 4)(cat)
    e = keras.layers.Flatten()(e)
    x = keras.layers.Concatenate()([num, e])
    x = keras.layers.Dense(32, activation="relu")(x)
    x = keras.layers.Dropout(.1)(x)
    x = keras.layers.Dense(16, activation="relu")(x)
    out = keras.layers.Dense(1)(x)
    model = keras.Model({"num": num, "cat": cat}, out)
    if task == "regression":
        loss = "mse"
        metrics = [keras.metrics.RootMeanSquaredError(name="rmse")]
    elif task == "binary":
        loss = keras.losses.BinaryCrossentropy(from_logits=True)
        metrics = [keras.metrics.AUC(from_logits=True, name="auc")]
    else:
        raise ValueError(task)
    model.compile(optimizer=keras.optimizers.Adam(.001), loss=loss, metrics=metrics)
    return model

29.6 ツリーベースモデルとの比較

表形式データでは勾配ブースティング決定木（GBDT）が強力な基準となる。木は特徴量の閾値による分割を組み合わせるため、非線形な相互作用を表現でき、一般に標準化を必要としない。LightGBM・XGBoost・CatBoostは代表的な選択肢であるが、カテゴリや欠損の処理仕様は異なる。MLPは滑らかな関数近似、Embedding、他モダリティとの統合に利点がある。どちらが優れるかはデータ依存である。

モデル利点注意点
線形モデル高速・解釈しやすい相互作用は特徴量化
GBDT閾値・相互作用に強い外挿が苦手な場合
MLP連続的表現・Embedding尺度・学習設定に敏感
コード29.4　非線形回帰の基準モデル比較
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.linear_model import Ridge
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.preprocessing import StandardScaler, PolynomialFeatures
from sklearn.pipeline import make_pipeline
from sklearn.metrics import mean_squared_error
rng = np.random.default_rng(29)
X = rng.uniform(-2, 2, (2000, 4))
y = 2*X[:,0]*X[:,1] + X[:,2]**2 + rng.normal(0,.4,len(X))
Xtr,Xva,ytr,yva = train_test_split(X,y,test_size=.25,random_state=29)
models = {"Ridge": make_pipeline(StandardScaler(), Ridge()),
          "Polynomial Ridge": make_pipeline(PolynomialFeatures(2), StandardScaler(), Ridge()),
          "HistGradientBoosting": HistGradientBoostingRegressor(random_state=29)}
scores = {}
for name, model in models.items():
    model.fit(Xtr,ytr)
    scores[name] = mean_squared_error(yva,model.predict(Xva))**.5
print(scores)

この実験では真の関数に二次の相互作用を含めたため、多項式特徴量が有利である。これは一般的なモデル順位ではない。MLPとの比較は後述の共通Foldで行う。

29.7 目的変数と評価指標の設計

価格など正の歪んだ目的変数ではlog1p変換が有効な場合がある。元の尺度に戻すにはexpm1を用いる。ただし対数空間の平均を逆変換しても元尺度の条件付き平均とは一般に一致しない。評価指標がRMSEなら元の尺度で検証する。RMSLEは非負の目的変数・予測値を前提とする。

$$\mathrm{RMSE}=\sqrt{\frac1N\sum_i(y_i-\hat y_i)^2}$$

分類ではBCEを学習に使い、ROC-AUC、Average Precision（AP）やPR曲線の面積、Log Lossなどコンペの指標で評価する。不均衡データでAccuracyだけを見ると多数派予測が高得点になる場合がある。クラス重みを適用した場合、出力確率の校正が変わることがあるので、独立した検証データで確認する。

指標予測形式注意点
RMSE実数外れ値の影響
RMSLE非負実数対数尺度
ROC-AUC連続スコア順位評価
Log Loss確率過信を罰する
F1クラス閾値を検証で選ぶ
コード29.5　分類の評価例（人工予測）
import numpy as np
from sklearn.metrics import roc_auc_score, average_precision_score, log_loss, f1_score
y = np.array([0, 0, 1, 0, 1, 1])
p = np.array([.1, .4, .35, .2, .8, .7])
print(roc_auc_score(y,p), average_precision_score(y,p), log_loss(y,p))
print(f1_score(y,p >= .5))

29.8 Foldごとの前処理とOOF予測

OOF（out-of-fold）予測では、各訓練行に対して、その行を学習に使用していないモデルの予測を保存する。全行のOOFをまとめて評価することで、Foldごとのサイズの違いも反映できる。ただしAUCなどではFold間のスコア尺度の違いにも注意する。RMSEはFold RMSEの単純平均と全OOFのRMSEが一致しないことに注意する。

外側Foldの評価を使って多数の設定を選べば、OOFも楽観的になる。最終評価には独立テストまたはNested CVが必要となる。テスト予測はFoldモデルの連続値や確率を平均する。分類のロジット平均と確率平均は一般に異なる。

29.9 実践：住宅価格の回帰パイプライン

以下では人工住宅データを生成し、面積・築年数・部屋数・地域から価格（任意の単位）を予測する。外部データのダウンロードは不要である。第29.5節のbuild_modelを先に実行する。外側5-Foldの訓練部分を内側訓練と検証に分け、数値補完・標準化・語彙を内側訓練だけから推定する。比較用GBDTも同じ内側訓練行を使う。価格は100で割り学習を安定させ、評価時に元尺度へ戻す。

コード29.6　データ生成とFold内前処理
import numpy as np
import pandas as pd
from sklearn.model_selection import KFold, train_test_split
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.metrics import mean_squared_error
rng = np.random.default_rng(29)
n = 1800
df = pd.DataFrame({"area": rng.uniform(20,150,n),
    "age": rng.uniform(0,45,n), "rooms": rng.integers(1,6,n),
    "region": rng.choice(["A","B","C","D"],n)})
y = (30 + 2*df.area - .8*df.age + 4*df.rooms
     + 20*(df.region=="A") + .01*df.area*df.rooms
     + rng.normal(0,8,n)).to_numpy(dtype="float32")
df.loc[rng.choice(n,100,replace=False),"area"] = np.nan
df.loc[rng.choice(n,60,replace=False),"region"] = None
train, test = df.iloc[:1500].copy(), df.iloc[1500:].copy()
y_train = y[:1500]
# テストの正解は最後まで使用しない
cols = ["area", "age", "rooms"]
def fit_preprocessor(frame):
    pipe = make_pipeline(SimpleImputer(strategy="median", add_indicator=True), StandardScaler())
    pipe.fit(frame[cols])
    vocab = {v:i+1 for i,v in enumerate(sorted(frame.region.fillna("__MISSING__").unique()))}
    return pipe, vocab

def transform(frame, pipe, vocab):
    num = pipe.transform(frame[cols]).astype("float32")
    cat = frame.region.fillna("__MISSING__").map(vocab).fillna(0).to_numpy(dtype="int32")[:,None]
    return {"num": num, "cat": cat}

def tree_input(x, vocab):
    onehot = np.eye(len(vocab)+1, dtype="float32")[x["cat"][:,0]]
    return np.concatenate([x["num"], onehot], axis=1)
コード29.7　OOF学習と提出ファイル作成
from pathlib import Path
import joblib
out = Path("run29")
out.mkdir(exist_ok=True)
oof = np.full(len(train), np.nan)
oof_tree = np.full(len(train), np.nan)
test_preds = []
for fold, (outer_tr, va) in enumerate(KFold(5, shuffle=True, random_state=29).split(train)):
    tr, es = train_test_split(outer_tr, test_size=.15, random_state=29+fold)
    keras.backend.clear_session()
    keras.utils.set_random_seed(29+fold)
    pipe, vocab = fit_preprocessor(train.iloc[tr])
    a,b,c,t = [transform(f,pipe,vocab) for f in (train.iloc[tr],train.iloc[es],train.iloc[va],test)]
    model = build_model(a["num"].shape[1],len(vocab)+1)
    model.fit(a,y_train[tr,None]/100,validation_data=(b,y_train[es,None]/100),
              epochs=100,batch_size=32,verbose=0,
              callbacks=[keras.callbacks.EarlyStopping(patience=10,restore_best_weights=True)])
    oof[va] = model.predict(c,verbose=0).ravel()*100
    test_preds.append(model.predict(t,verbose=0).ravel()*100)
    model.save(out/f"fold{fold}.keras")
    joblib.dump((pipe,vocab),out/f"prep{fold}.joblib")
    tree = HistGradientBoostingRegressor(random_state=29,early_stopping=False)
    tree.fit(tree_input(a,vocab),y_train[tr])
    oof_tree[va] = tree.predict(tree_input(c,vocab))
assert np.isfinite(oof).all() and np.isfinite(oof_tree).all()
print("MLP OOF RMSE",mean_squared_error(y_train,oof)**.5)
print("GBDT OOF RMSE",mean_squared_error(y_train,oof_tree)**.5)
pred = np.mean(test_preds,axis=0)
pd.DataFrame({"id":test.index,"price":pred}).to_csv(out/"submission.csv",index=False)
pd.DataFrame({"id":train.index,"target":y_train,"mlp":oof,"gbdt":oof_tree}).to_csv(out/"oof.csv",index=False)

ここでは提出例としてMLPの予測を固定採用する。OOFの比較結果を見てモデルを選ぶ場合は別途独立評価を行う。実際のKaggleではsample_submission.csvのID順・列名・行数と一致するように結合し、重複や欠落を検査する。joblibファイルは信頼できる自分の成果物のみ読み込む。TensorFlowによる学習結果は実行して確認すること。

29.10 実践：二値分類への変更

顧客離脱などの二値分類では、出力は1ロジットとしBCEを用いる。外側・内側の分割はクラス比を維持する層化分割に置き換える。以下は前節の人工住宅データを「高価格帯か」という二値分類に変更する前節のコード29.3・29.6を実行してから取り組む演習である。閾値200は事前固定する。評価には確率を用いる。

コード29.8　層化分割による二値分類の学習
from sklearn.model_selection import StratifiedKFold
from sklearn.metrics import roc_auc_score, log_loss
import tensorflow as tf
labels = (y_train >= 200).astype("float32")
probs = np.full(len(train),np.nan)
for fold,(outer_tr,va) in enumerate(StratifiedKFold(5,shuffle=True,random_state=29).split(train,labels)):
    tr,es = train_test_split(outer_tr,test_size=.2,stratify=labels[outer_tr],random_state=29+fold)
    keras.backend.clear_session()
    keras.utils.set_random_seed(29+fold)
    pipe,vocab = fit_preprocessor(train.iloc[tr])
    a,b,c = [transform(train.iloc[i],pipe,vocab) for i in (tr,es,va)]
    model = build_model(a["num"].shape[1],len(vocab)+1,task="binary")
    model.fit(a,labels[tr,None],validation_data=(b,labels[es,None]),
              epochs=60,batch_size=32,verbose=0,
              callbacks=[keras.callbacks.EarlyStopping(patience=8,restore_best_weights=True)])
    probs[va] = tf.sigmoid(model.predict(c,verbose=0)).numpy().ravel()
assert np.isfinite(probs).all()
print("AUC",roc_auc_score(labels,probs),"Log Loss",log_loss(labels,probs))

実務では少数クラス数がFold数を下回らないか、各検証部分に両クラスが存在するかを確認する。閾値を最適化するなら外側検証ラベルに依存しない手順を設計する。

29.11 性能改善と実験管理

基準モデルを構築した後、特徴量、埋め込み幅、隠れ層、Dropout、学習率を一つずつ変更する。特徴量群を外して性能を比較するアブレーションは有効だが、相関した特徴量の寄与は単独では判断しにくい。Permutation Importanceも相関や分布外の組み合わせに注意する。訓練データとテストの分布差、欠損率や未知カテゴリ率の変化を監視する。

症状確認項目対策候補
訓練も検証も悪い尺度・ラベル・容量前処理確認、学習率調整
訓練のみ良い過学習・リーク正則化、分割見直し
Fold間の差が大きいグループ・分布差分割設計の再検討

29.12 まとめと確認問題

表形式データでは、モデルの高度さよりも予測時点に整合する特徴量、検証設計、前処理の再現性が重要になる。MLPとGBDTの両方を基準にして、実験結果に基づいて改善する。

問1　カテゴリIDを直接数値特徴にする問題は？

根拠のない大小関係を与える。

問2　前処理のfitはどの行で行うか？

各Foldの内側訓練行だけ。

問3　Embeddingの語彙100、幅8のパラメータ数は？

800。語彙数にOOV等を含む。

問4　GBDTに標準化は必須か？

一般には不要。

問5　OOFの意味は？

各行を学習に用いていないモデルによる予測。

問6　RMSEをFoldごとに平均する場合の注意は？

全OOFのRMSEとは一般に一致しない。

問7　BCEのロジットを確率にするには？

Sigmoidを適用する。

問8　テストで未知カテゴリが出た場合は？

固定済みのOOV IDに変換する。

問9　発展：EmbeddingをOne-hotへ変更して比較せよ。

同一Fold・前処理・シードで、カテゴリIDをOOVを含む語彙数VのOne-hotへ変換し、結合する。コード29.6のtree_input(a, vocab)と同様に変換し、EmbeddingなしのDenseモデルに入力する。数値入力幅をpとすると、最初のDenseとEmbeddingの合計は4V+32(p+5)、One-hot方式では32(p+V+1)となる（バイアスあり）。OOF RMSEとモデル容量を比較し、独立テストで選択結果を検証する。

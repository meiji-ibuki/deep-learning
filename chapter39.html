39.1 コンペティションの全体像

本章では第1〜38章の知識を、未知データに対する予測性能を競うKaggleコンペティションへ統合する。典型的な教師あり予測コンペでは、正解付き訓練データと正解が非公開のテストデータが配布される。評価指標に従って予測を提出し、順位を比較する。コンペによってはNotebook実行による提出や、対戦・審査方式もある。

目標は公開順位だけを上げることではなく、未知標本への汎化性能を再現可能な実験で改善することである。まず小さなモデルで提出まで通し、次に検証を信頼できるものにしてから複雑化する。

39.2 コンペの選び方とルール

初参加なら、データ量・計算予算・評価指標・締切を確認し、既習の表形式や画像分類から始める。練習用コンペと期限付きコンペは目的が異なる。Overview、Data、Evaluation、Rules、Code、Discussionを確認する。外部データ、事前学習済み重み、インターネット接続、チーム外共有、提出回数、最終提出選択、ライセンスの制限はコンペ固有である。

確認対象記録する内容
評価指標、最大化／最小化、提出値の意味
データ観測単位、ID、時刻、グループ、欠損
提出CSVまたはNotebook、列名、時間制限
規約外部資源、共有、参加・提出期限

公開Notebookを参考にするときも、コードとデータの利用条件を確認し、出典を残す。理解しないままコピーせず、各処理の目的を検証する。

39.3 データの確認とEDA

以下は外部ファイル不要の模擬二値分類コンペである。人工データを生成し、訓練・模擬テストを分ける。模擬テストの真値は最後の評価まで使わない。実コンペでは真値を得られない。コード39.1〜39.9は順に同一セッションで実行する（コード39.5はTensorFlowを使う任意の比較であり、最終候補には含めない）。

EDAでは行列サイズ、型、欠損、重複、IDの一意性、目的変数の比率、分布差、特徴間の関連を確認する。予測時点で利用できない特徴は除外する。テストの分布確認は規約に従い、前処理の学習は訓練Fold内に限定する。

コード39.1　模擬コンペデータの生成
import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split, StratifiedKFold
from sklearn.metrics import log_loss, roc_auc_score
rng=np.random.default_rng(39)
x=rng.normal(size=(2400,5))
z=1.4*x[:,0]-x[:,1]+1.7*x[:,2]*x[:,3]+0.5*x[:,4]
y=(rng.random(len(z))<1/(1+np.exp(-z))).astype(int)
x[rng.random(x.shape)<0.06]=np.nan
frame=pd.DataFrame(x,columns=list('abcde'))
frame.insert(0,'id',np.arange(len(x)))
train,test=train_test_split(frame,test_size=.25,random_state=39,stratify=y)
train=train.copy(); test=test.copy()
train['target']=y[train.id.to_numpy()]
heldout_y=y[test.id.to_numpy()]
features=list('abcde')
print(train.shape,test.shape,train.target.mean())
print(train[features].isna().mean())
assert train.id.is_unique and test.id.is_unique
assert not set(train.id)&set(test.id)

39.4 検証戦略とデータリーク

検証分割は実際の予測条件を模倣する。独立同分布とみなせる標本の分類ならStratified K-Fold、同一人物や店舗が複数行ならGroup K-Fold、未来予測なら時間順の分割を使う。重複画像や同一動画のフレームもグループ化する。ラベル生成に使われた事後情報や、全データで学習したTarget Encodingは典型的なリークである。

外側Foldは評価専用とし、Early Stoppingや探索には内側分割を使う。繰り返し同じCVを最適化するとCVにも過適合する。最終的な性能推定には独立ホールドアウトやNested CVを検討する。

コード39.2　固定Foldと評価関数
cv=StratifiedKFold(n_splits=5,shuffle=True,random_state=39)
X=train[features]; Y=train.target.to_numpy(); Xt=test[features]
splits=list(cv.split(X,Y))
counts=np.zeros(len(Y),int)
for tr,va in splits:
    assert not np.intersect1d(tr,va).size
    counts[va]+=1
assert np.all(counts==1)
def evaluate(y,p):
    return {'logloss':log_loss(y,p,labels=[0,1]),'auc':roc_auc_score(y,p)}

39.5 ベースラインの構築

最初は単純なモデルを使う。二値分類でLog Lossを最小化するとき、予測はクラスラベルでなく正例確率である。

$$L=-\frac1N\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]$$

定数予測は学習Foldの正例率を使用する。ロジスティック回帰は欠損補完と標準化をPipeline内に入れ、Foldごとに学習し直す。非線形性を表現できるGBDTも比較対象にする。深層学習が常に優れるとは限らない。

コード39.3　定数・線形・GBDTのOOF予測
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.base import clone
models={'linear':make_pipeline(SimpleImputer(strategy='median'),StandardScaler(),LogisticRegression()),
        'gbdt':HistGradientBoostingClassifier(max_iter=100,max_leaf_nodes=15,random_state=39)}
oof={k:np.zeros(len(Y)) for k in ['constant',*models]}
pred={k:[] for k in oof}
for tr,va in splits:
    oof['constant'][va]=Y[tr].mean(); pred['constant'].append(np.full(len(Xt),Y[tr].mean()))
    for name,base in models.items():
        m=clone(base).fit(X.iloc[tr],Y[tr])
        oof[name][va]=m.predict_proba(X.iloc[va])[:,1]
        pred[name].append(m.predict_proba(Xt)[:,1])
print({k:evaluate(Y,v) for k,v in oof.items()})

39.6 深層学習モデルへの展開

Tabular MLPでは欠損補完、標準化、Dense層、Dropoutを組み合わせる。画像なら第30章、テキストなら第32章、時系列なら第33章の入力処理へ置き換える。以下は同じ外側FoldでMLPを評価する任意実習。内側検証によってエポック数を決め、外側訓練全体で再学習する。外側検証をEarly Stoppingに使わない。

コード39.4　MLP用のFold内前処理
def preprocess_fit(x):
    return make_pipeline(SimpleImputer(strategy='median'),StandardScaler()).fit(x)
from sklearn.model_selection import train_test_split
for tr,va in splits:
    inner,stop=train_test_split(tr,test_size=.2,random_state=39,stratify=Y[tr])
    assert not np.intersect1d(stop,va).size
    prep=preprocess_fit(X.iloc[inner])
    assert np.isfinite(prep.transform(X.iloc[stop])).all()
コード39.5　内側検証と再学習によるMLPのOOF予測（任意）
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers
def build(seed):
    keras.utils.set_random_seed(seed)
    m=keras.Sequential([keras.Input((len(features),)),layers.Dense(64,activation='relu'),layers.Dropout(.15),layers.Dense(32,activation='relu'),layers.Dense(1,activation='sigmoid')])
    m.compile(optimizer='adam',loss='binary_crossentropy')
    return m
mlp_oof=np.zeros(len(Y)); mlp_pred=[]
for fold,(tr,va) in enumerate(splits):
    inner,stop=train_test_split(tr,test_size=.2,random_state=39,stratify=Y[tr])
    prep=preprocess_fit(X.iloc[inner]); m=build(39+fold)
    h=m.fit(prep.transform(X.iloc[inner]),Y[inner],validation_data=(prep.transform(X.iloc[stop]),Y[stop]),epochs=60,batch_size=64,verbose=0,callbacks=[keras.callbacks.EarlyStopping(patience=6)])
    best=int(np.argmin(h.history['val_loss']))+1
    prep=preprocess_fit(X.iloc[tr]); m=build(39+fold)
    m.fit(prep.transform(X.iloc[tr]),Y[tr],epochs=best,batch_size=64,verbose=0)
    mlp_oof[va]=m.predict(prep.transform(X.iloc[va]),verbose=0).ravel()
    mlp_pred.append(m.predict(prep.transform(Xt),verbose=0).ravel())
    keras.backend.clear_session()
print(evaluate(Y,mlp_oof))

39.7 スコア改善と誤差分析

改善は仮説から始める。線形モデルが相互作用を表現できないなら積特徴を加える。欠損が情報を持つなら欠損フラグを検討する。分類では確信度が高い誤分類を調べ、回帰では残差の分布や極端値を確認する。サブグループ別の性能も確認するが、小標本の差を過信しない。

変更は原則一つずつ、同じFoldで比較する。探索の途中でテスト真値を使わない。以下の誤差分析はOOF予測に限る。

コード39.6　OOF誤差とサブグループ分析
err=train[['id','target']].copy()
err['p']=oof['gbdt']
err['loss']=-Y*np.log(np.clip(err.p,1e-7,1))-(1-Y)*np.log(np.clip(1-err.p,1e-7,1))
err['missing']=X.isna().any(axis=1).to_numpy()
print(err.groupby('missing').loss.agg(['mean','count']))
print(err.nlargest(5,'loss'))

39.8 OOF予測とアンサンブル

Foldごとのテスト予測を平均することで分割によるばらつきを抑えられる場合がある。ただしOOFは各行について1モデルの予測であり、Fold平均したテスト予測の性能を直接評価したものではない。異なるモデルの予測も平均できる。

$$\hat p(x)=\sum_m w_m\frac1K\sum_{k=1}^K p_{mk}(x),\qquad w_m\ge0,\quad\sum_m w_m=1$$

ここでは事前に固定した等重みを比較する。OOFを使って重みを最適化する場合、その同じOOFで評価すると選択バイアスが生じるため、独立検証が望ましい。AUCとLog Lossは異なる性質を持つため、目的指標に合わせる。

コード39.7　等重みアンサンブル
oof['blend']=(oof['linear']+oof['gbdt'])/2
p_linear=np.mean(pred['linear'],axis=0)
p_gbdt=np.mean(pred['gbdt'],axis=0)
p_blend=(p_linear+p_gbdt)/2
print(evaluate(Y,oof['blend']))

39.9 提出ファイルの作成と検査

提出ファイルはsample_submissionを基準とする。IDの順序を勝手に仮定せず、IDで照合する。列名、行数、重複、欠損、有限性、確率範囲、クラス順を検査する。以下では模擬sample_submissionの順序を意図的に変え、IDによる対応を確認する。実際の提出は行わない。

コード39.8　提出CSVの生成と検証
sample=pd.DataFrame({'id':test.id.to_numpy()[::-1],'target':0.0})
lookup=pd.Series(p_blend,index=test.id.to_numpy())

39.10 Leaderboardとの付き合い方

典型的な予測コンペではPublic Leaderboardはテストの一部分、Private Leaderboardは別の部分に基づく。公開スコアを見ながら多数のモデルを選ぶと、公開部分の偶然に適応して非公開部分で悪化する。公開順位は診断の補助にし、局所CVと予測の妥当性を優先する。

次の模式実験では、真の品質が同じ100候補に独立な公開・非公開ノイズを与える。公開上位を選ぶだけで公開値が楽観的になる。実際のコンペでは候補間相関や分布差もあるため、数値は一般化できない。

39.11 実験管理と最終提出

実験ID、データ版、Fold、乱数、特徴、モデル設定、指標、時間、保存先を記録する。Gitでコードを管理し、大きい重みや秘密情報を公開リポジトリに入れない。Notebookは上から実行して再現できることを確認する。GPU利用時間、外部データの条件、推論制限は規約に従う。最終提出の選択数・期限もコンペごとに確認する。

模擬テストはここで初めて評価する。候補はOOFのLog Lossで選択し、模擬テストの結果で選び直さない。

コード39.9　実験記録と最終評価
import json
from pathlib import Path
scores={k:evaluate(Y,v) for k,v in oof.items()}
best_name=min(scores,key=lambda k:scores[k]['logloss'])
all_test={k:np.mean(v,axis=0) for k,v in pred.items()}; all_test['blend']=p_blend
report={'seed':39,'folds':5,'features':features,'cv':scores,'selected':best_name}
Path('experiment39.json').write_text(json.dumps(report,indent=2))

print('selected',best_name,'mock holdout',evaluate(heldout_y,final_p))

assert list(final_submission.columns)==list(sample.columns)
assert final_submission.id.equals(sample.id) and final_submission.id.is_unique
assert len(final_submission)==len(test)

39.12 まとめと確認問題

コンペの基本は、規約確認→EDA→検証設計→ベースライン→改善→提出検査→再現性確認である。提出順位に依存しない評価戦略を持つことが重要である。次章では総合演習として一連の作業をより本格的に統合する。

問1　正例確率を提出する指標の例は？

二値分類のLog Loss。

問2　同じ患者の複数行はどう分割する？

患者IDでグループ分割する。

問3　標準化を全訓練データで先に行う問題は？

検証Foldの統計が学習に混入する。

問4　外側FoldをEarly Stoppingに使わない理由は？

評価データで学習設定を選ぶことになるため。

問5　OOFとは？

各行を学習に含まないFoldモデルによる予測。

問6　公開順位だけで選択する危険は？

公開テストへの過適合。

問7　提出IDの順序が異なるときは？

IDで対応付けてsample_submissionの順序を保つ。

問8　外部データを使えるか？

個別コンペの規約を確認する。

問9　発展：特徴aとbの交互作用を追加して比較せよ。

コード39.3の線形モデルを基準に、a×bの列を訓練・模擬テストに追加し、同じFoldとPipelineで比較する。欠損は積にも伝播させ、Fold内で補完する。OOF損失と計算時間を記録する。なお生成式の真の交互作用はc×dであるため、a×bで改善する保証はない。模擬テストを選択に使わない。再計算例：線形モデルのOOF Log Lossは0.569735、a×b追加後は0.570904。

15.1 学習から推論までの全体像

第14章ではネットワークの構造を定義しました。しかし、モデルを作るだけでは予測器として使えません。損失を定義し、訓練データで重みを更新し、未知のデータで性能を確かめてから推論に進みます。本章ではTensorFlow 2系・Keras 3の tf.keras を使います。

メソッド役割重みの更新
compile学習方法を設定なし
fit訓練と検証訓練時のみ
evaluate損失・指標を集計なし
predict予測を返すなし

検証データは学習率調整やモデル選択に使うため、完全に独立した性能評価ではありません。テストデータは最後まで温存します。Kaggleのテストデータは通常ラベルがなく、提出用の予測を生成する対象です。

15.2 compile：学習の設定

compileは学習の契約を決める操作です。optimizerは勾配をどう更新に変換するか、lossは何を最小化するか、metricsは何を観測するかを指定します。評価指標は通常、直接の最適化対象ではありません。

コード15.1　共通準備と二値分類モデル
import numpy as np
import tensorflow as tf
from tensorflow import keras
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

keras.utils.set_random_seed(42)
X, y = make_classification(n_samples=1000, n_features=10,
                           n_informative=6, random_state=42)
X = X.astype('float32')
y = y.astype('float32').reshape(-1, 1)
X_dev, X_test, y_dev, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)
X_train, X_val, y_train, y_val = train_test_split(
    X_dev, y_dev, test_size=0.25, stratify=y_dev, random_state=42)

def build_model():
    norm = keras.layers.Normalization()
    norm.adapt(X_train)
    model = keras.Sequential([
        keras.Input(shape=(10,)), norm,
        keras.layers.Dense(32, activation='relu'),
        keras.layers.Dense(16, activation='relu'),
        keras.layers.Dense(1)])
    model.compile(optimizer=keras.optimizers.Adam(0.001),
                  loss=keras.losses.BinaryCrossentropy(from_logits=True),
                  metrics=[keras.metrics.BinaryAccuracy(threshold=0.0, name='acc'),
                           keras.metrics.AUC(from_logits=True, name='auc')])
    return model

model = build_model()

出力はロジットなのでBinaryAccuracyの閾値は0です（厳密に0より大きいとき陽性）。後述のF1用の閾値判定は以上（≥）を採用するため、境界値の規則が異なります。AUCにもロジットであることを指定します。KerasのAUCは有限個の閾値に基づく近似値であり、順位に基づく厳密なROC-AUCと一致するとは限りません。標準化層は訓練データだけでadaptし、モデルと一緒に保存できるようにしました。再compileは既存の重みを初期化しませんが、別のoptimizerを渡せばその内部状態は新しくなります。

タスク出力lossmetricsの例
回帰線形MSEMAE
二値分類ロジット1個BCE(from_logits=True)BinaryAccuracy(threshold=0), AUC(from_logits=True)
多クラス分類K個のロジットSparse CCE(from_logits=True)SparseCategoricalAccuracy

15.3 fit：エポック・バッチ・ステップ

エポックは通常、訓練データ全体を一巡する単位です。バッチは一回の更新に使う標本の集まりで、ステップは通常その処理回数です。配列600件を32件ずつ処理すると、端数を含め19ステップになります。

$$S=\lceil N/B\rceil=\lceil600/32\rceil=19$$
コード15.2　基本の学習
history = model.fit(X_train, y_train,
                    validation_data=(X_val, y_val),
                    epochs=5, batch_size=32, shuffle=True, verbose=2)
print(history.history.keys())

epochsは最大の終了エポック番号です。initial_epoch=5, epochs=10なら5エポック分を追加します。validation_splitは配列の末尾から検証分を取り出してからシャッフルするため、時系列やグループがある場合には明示的なvalidation_dataを使います。DatasetではbatchサイズやshuffleをDataset側で指定します。repeatした無限Datasetではsteps_per_epochが必要です。通常の配列入力では指定不要です。

15.4 Historyと学習曲線

Historyには各エポックの訓練・検証指標が辞書形式で記録されます。訓練損失は更新途中のモデルの集計、検証損失はエポック終了時のモデルで計算されます。したがって両者の差だけで過学習を断定できません。

コード15.3　学習曲線の描画
import matplotlib.pyplot as plt

def plot_history(history):
    h = history.history
    epochs = history.epoch
    fig, ax = plt.subplots(1, 2, figsize=(10, 4))
    for i, key in enumerate(['loss', 'auc']):
        ax[i].plot(np.array(epochs)+1, h[key], label='train')
        ax[i].plot(np.array(epochs)+1, h['val_'+key], label='validation')
        ax[i].set(xlabel='Epoch', ylabel=key)
        ax[i].legend()
    plt.tight_layout()
    plt.show()

plot_history(history)

15.5 Callbacks：学習を制御する

Callbackは学習の各段階で呼び出される処理です。検証指標を監視して停止・保存・学習率変更を自動化できます。監視対象がlossなら通常min、AUCならmaxを選びます。

Callback用途主な引数
EarlyStopping改善停止時に学習終了monitor, patience, min_delta, restore_best_weights
ModelCheckpoint最良モデルの保存filepath, save_best_only, mode
ReduceLROnPlateau改善停止時に学習率低下factor, patience, min_lr
CSVLogger履歴をCSVへ記録filename, append
TerminateOnNaNNaN損失で停止—
BackupAndRestore中断からの復旧backup_dir
コード15.4　コールバック付き学習
from pathlib import Path
from tempfile import mkdtemp
run = Path(mkdtemp(prefix='run15-', dir='.'))
model = build_model()
callbacks = [
    keras.callbacks.ModelCheckpoint(str(run/'best.keras'),
        monitor='val_loss', mode='min', save_best_only=True),
    keras.callbacks.ReduceLROnPlateau(monitor='val_loss', mode='min',
        factor=0.5, patience=3, min_lr=1e-6),
    keras.callbacks.EarlyStopping(monitor='val_loss', mode='min',
        patience=8, restore_best_weights=True),
    keras.callbacks.CSVLogger(str(run/'history.csv')),
    keras.callbacks.TerminateOnNaN()]
history = model.fit(X_train, y_train, validation_data=(X_val, y_val),
                    batch_size=32, epochs=80, callbacks=callbacks, verbose=2)
plot_history(history)

学習率を下げた後に改善の機会を与えるため、EarlyStoppingのpatienceを長めにしています。これは出発点であり最適値ではありません。EarlyStoppingの重み復元はoptimizer状態まで最良時点に戻すものではないため、再学習には保存したモデルを利用します。コールバックは実験ごとに新しく生成し、保存先も分離してください。古いチェックポイントの誤読を防ぐため、この例では実行ごとに新しいディレクトリを作成します。

15.6 evaluate：未知データで評価する

evaluateはモデルを推論モードで実行し、損失と指標を集約します。検証データでモデルや閾値を決定した後、独立テストを一度評価します。return_dict=Trueなら指標名と値の対応を明示できます。

コード15.5　最良モデルの評価
assert np.isfinite(history.history['val_loss']).any(), "有限の検証損失がありません"
assert (run/'best.keras').is_file(), "チェックポイントがありません"
best = keras.models.load_model(str(run/'best.keras'))
val_scores = best.evaluate(X_val, y_val, verbose=0, return_dict=True)
print(val_scores)

バッチごとの指標を単純平均すると、端数バッチの重みが不適切になる場合があります。AUCやF1は特に全標本の予測を集計するか、全バッチにわたって必要な統計量を累積する必要があります。sample_weightは損失に適用されますが、compileのmetricsに指定した指標には原則適用されません。重み付き指標はweighted_metricsを使います。

15.7 predict：予測値を取り出す

predictはバッチ処理された予測をNumPy配列などで返します。少数の入力ならmodel(x, training=False)も便利です。Dropoutは推論時には無効になり、Batch Normalizationは通常移動統計量を使います。ロジットを確率へ変換してから閾値判定を行います。

コード15.6　予測確率と検証データでの閾値決定
from sklearn.metrics import f1_score
val_logits = best.predict(X_val, batch_size=128, verbose=0)
val_p = tf.sigmoid(val_logits).numpy().ravel()
thresholds = np.linspace(0.1, 0.9, 81)
f1s = [f1_score(y_val.ravel(), val_p >= t, zero_division=0)
       for t in thresholds]
threshold = float(thresholds[np.argmax(f1s)])
print(threshold)
# 閾値を確定してからテストデータを評価
scores = best.evaluate(X_test, y_test, verbose=0, return_dict=True)
test_p = tf.sigmoid(best.predict(X_test, verbose=0)).numpy().ravel()
print(scores, f1_score(y_test.ravel(), test_p >= threshold))

Log LossやAUCを提出する場合は通常、閾値処理せず確率または指定されたスコアを提出します。多クラスはsoftmax(axis=-1)、ラベル予測はargmax(axis=-1)、マルチラベルはラベルごとにsigmoidを使います。predictでデータをシャッフルしないことも重要です。

15.8 モデルの保存・復元と学習再開

保存方法保存内容・用途
model.save("model.keras")構造・重み・コンパイル情報・optimizer状態（対応する場合）
model.save_weights("model.weights.h5")重み中心。復元先のモデル構造を用意する。Kerasのバージョン・保存条件によってはoptimizer状態も含むため、学習再開には全体モデル保存を推奨
model.export("saved_model")TensorFlow SavedModelとして推論用にエクスポート
コード15.7　モデル保存と復元の検証
best.save(str(run/'final.keras'))
restored = keras.models.load_model(str(run/'final.keras'))
np.testing.assert_allclose(best.predict(X_val, verbose=0),
                           restored.predict(X_val, verbose=0),
                           rtol=1e-5, atol=1e-6)
best.save_weights(str(run/'final.weights.h5'))
clone = build_model()
clone.load_weights(str(run/'final.weights.h5'))
np.testing.assert_allclose(best.predict(X_val, verbose=0),
                           clone.predict(X_val, verbose=0), atol=1e-6)

独自レイヤーや損失を保存する場合は登録・シリアライズ設定が必要です。Keras 3ではSavedModelをload_modelで直接読み込む方式ではなく、推論用にはtf.saved_model.loadやTFSMLayerなどを利用します。外部の前処理器、特徴量順序、閾値、乱数シード、ライブラリのバージョンも保存してください。全体モデルを復元してもデータのシャッフル状態やコールバック状態が完全に復元されるとは限りません。

コード15.8　学習を追加する例（独立した実験として実行）
resume = keras.models.load_model(str(run/'best.keras'))
# 保存した時点の重みとoptimizer状態から追加学習
extra = resume.fit(X_train, y_train, validation_data=(X_val, y_val),
                   epochs=3, batch_size=32, verbose=2)

上の追加学習は別実験です。テスト結果を見て再調整しないでください。途中中断の復旧はBackupAndRestoreを検討し、最良モデルの保存先とは分離します。

15.9 実践：Kaggle形式の学習・推論パイプライン

ここまでの人工データをKaggle形式に見立て、IDと予測の対応を保った提出ファイルを作ります。実際のコンペではsample_submission.csvの列名・順序・予測形式を確認します。以下は実コンペに提出するファイルではありません。

コード15.9　提出ファイルと実験メタデータ
import pandas as pd
import json

# 人工データのテスト標本に対応する模擬ID
ids = np.arange(len(X_test)) + 10000
submission = pd.DataFrame({'id': ids, 'target': test_p})
assert len(submission) == len(X_test)
assert submission['id'].is_unique
assert np.isfinite(submission['target']).all()
assert submission['target'].between(0, 1).all()
submission.to_csv(run/'submission.csv', index=False)
with open(run/'metadata.json', 'w', encoding='utf-8') as f:
    json.dump({'threshold': threshold, 'seed': 42,
               'tensorflow': tf.__version__, 'n_features': 10}, f, indent=2)
print(submission.head())

実際のテストIDは元データから保持し、sample_submissionのID順に結合します。欠損や重複がないこと、予測確率の範囲が正しいことをチェックします。CVではfoldごとに独立したモデル・前処理・コールバックを作り、OOF予測を保存して検証します。詳しくは第22・37・39章で扱います。

本章のTensorFlowコードは構文検証済みですが、制作環境では実行していません。学習曲線は模式図であり、精度の実測値は掲載していません。コードは同じNotebookで上から順に実行してください。

15.10 まとめと確認問題

compileで学習目標を設定し、fitで訓練、HistoryとCallbacksで監視し、evaluateで評価、predictで予測を生成します。最良モデルを保存して、同じ前処理と出力変換を推論時に再現できることが重要です。

問1　100件、バッチサイズ32の更新回数は？

端数を使う場合4回。

問2　ロジットを出力する二値分類のAccuracy閾値は？

0。確率の場合は0.5。

問3　validation_splitを時系列で安易に使わない理由は？

配列の末尾を切り出すだけであり、時点やグループの境界を自動で検証しないため。

問4　検証損失が最小のモデルを保存する設定は？

ModelCheckpoint(filepath="best.keras", monitor="val_loss", mode="min", save_best_only=True)。

問5　EarlyStoppingで重みを復元するとoptimizerも復元されるか？

重み復元だけでは最良時点のoptimizer状態は復元されない。

問6　AUCを各バッチで計算し平均してよいか？

一般に不可。全標本を集計する指標を使う。

問7　predictの出力がロジットの場合、確率提出には何が必要か？

二値分類ならsigmoid、多クラスならsoftmax。

問8　モデル以外に保存すべきものは？

前処理、特徴量順、閾値、実験設定、バージョンなど。

発展演習：最良エポックの特定

Historyから検証損失が最小のエポックを取得し、保存したモデルの検証損失と比較してください。NaN・Infは除外し、有限値がない場合は失敗として扱います。

解答・実装例
コード15.10　最良エポックの確認
import numpy as np
v = np.asarray(history.history['val_loss'])
valid = np.isfinite(v)
assert valid.any()
i = int(np.argmin(np.where(valid, v, np.inf)))
print('best epoch:', history.epoch[i] + 1, 'loss:', v[i])
print(best.evaluate(X_val, y_val, batch_size=32, return_dict=True, verbose=0)['loss'])

コード15.1〜15.7で用意したhistory・best・検証データを使います。有限の検証損失を持つ最良時点の重みが保存され、同じ検証条件なら復元後の評価は通常ほぼ一致します。浮動小数点演算や集計順序によるわずかな差はあり得ます。

40.1 総合演習の課題と成功条件

本章は第1〜39章の総合演習である。架空の住宅設備の故障リスクを予測する二値分類コンペを想定する。目的は未知の設備に対する故障確率を推定し、Log Lossを最小化すること。設備ごとに複数の観測があるため、行単位のランダム分割ではなく設備単位で検証する。実際のKaggleコンペではなく、外部ファイル不要の教材である。

成果物は再現可能な学習コード、固定Fold、OOF予測、モデル比較表、提出CSV、実験記録である。深層学習が必ずGBDTに勝つことは成功条件ではない。検証の信頼性と改善の根拠を説明できることを重視する。

コード40.1〜40.4、40.7〜40.10はTensorFlowなしで実行できる。コード40.5〜40.6はTensorFlowを導入した環境で追加実行する（CPUでも実行可能）。順番に同一セッションで実行する。最終評価はすべての候補と選択規則を固定してから一度だけ行う。

40.2 データ生成とコンペ形式の準備

設備ID、温度、振動、稼働時間、設備型式を観測する。温度と振動の交互作用、型式差、設備固有の未観測効果を含む人工データを生成する。目的変数は確率的に発生するため完全な予測は期待できない。設備IDは分割・照合のために使い、特徴量から除く。故障後の情報は使わない。

コード40.1　模擬データを生成する
import numpy as np
import pandas as pd
from sklearn.model_selection import GroupShuffleSplit, GroupKFold
from sklearn.metrics import log_loss, roc_auc_score
rng=np.random.default_rng(40)
group=np.repeat(np.arange(600), 5)
n=len(group)
kind=rng.choice(['A','B','C'],600)[group]
temp=rng.normal(size=n); vib=rng.normal(size=n)
hours=rng.uniform(0, 1, n)
z=-.7+temp+.8*vib+1.6*temp*vib+hours+(.8*(kind=='C'))+rng.normal(0,.7,600)[group]
y=(rng.random(n)<1/(1+np.exp(-z))).astype(int)
df=pd.DataFrame({'id':np.arange(n),'group':group,'temp':temp,'vib':vib,'hours':hours,'kind':kind})
for col in ['temp','vib','kind']:
    df.loc[rng.random(n)<.07,col]=np.nan
tr,te=next(GroupShuffleSplit(n_splits=1,test_size=.2,random_state=40).split(df,y,group))
train=df.iloc[tr].reset_index(drop=True); test=df.iloc[te].reset_index(drop=True)
Y=y[tr]; hidden_y=y[te]
assert not set(train.group)&set(test.group)
print(train.shape,test.shape,Y.mean())

40.3 EDAと検証設計

同一設備内の観測には相関がある。新設備への汎化が課題なのでGroupKFoldを使う。時系列の未来予測なら別途時間制約も必要である。欠損率、型式別の件数・故障率を調べ、少数グループで推定が不安定な点に注意する。模擬テストのラベルは参照しない。

コード40.2　EDAと固定Fold
print(train.isna().mean())
print(train.assign(target=Y).groupby('kind',dropna=False).target.agg(['size','mean']))
splits=list(GroupKFold(5).split(train,Y,train.group))
counts=np.zeros(len(Y),int)
for a,b in splits:
    assert not set(train.group.iloc[a])&set(train.group.iloc[b])
    counts[b]+=1

40.4 特徴量と前処理

数値は中央値補完と標準化、カテゴリは欠損を独立カテゴリとして扱いOne-hot化する。未知カテゴリはOne-hotの該当ブロックをすべて0にする設定とする。前処理の統計量は各Foldの訓練部分のみで推定する。交互作用は予測時点で利用可能な各行の説明変数だけから算出し、他の行やラベルから統計量を推定しないため、分割前に計算しても情報リークは生じない。ただしその採否は検証で判断する。

コード40.3　特徴量と前処理の定義
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder

def features(frame, interaction=False):
    x=frame[['temp','vib','hours','kind']].copy()
    if interaction: x['interaction']=x.temp*x.vib
    return x

def preprocessor(interaction=False):
    nums=['temp','vib','hours']+(['interaction'] if interaction else [])
    return ColumnTransformer([
        ('num',make_pipeline(SimpleImputer(strategy='median',add_indicator=True),StandardScaler()),nums),
        ('cat',make_pipeline(SimpleImputer(strategy='constant',fill_value='missing'),OneHotEncoder(handle_unknown='ignore')),['kind'])],sparse_threshold=0)

40.5 ベースラインの構築

定数モデル、ロジスティック回帰、交互作用付きロジスティック回帰、GBDTを比較する。評価指標は第10章・第22章で学んだ交差エントロピーである。

$$L=-\frac1N\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]$$

確率の質を測るLog Lossを主指標とし、順位識別能力のAUCを副指標とする。Foldごとに独立した前処理とモデルを学習し、各訓練行に一つのOOF予測を格納する。

コード40.4　ベースラインのOOF学習
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import HistGradientBoostingClassifier

def score(y,p):
    return {'logloss':float(log_loss(y,p,labels=[0,1])), 'auc':float(roc_auc_score(y,p))}
oof={}; predictions={}; fold_scores={}
for name,inter in [('linear',False),('interaction',True),('gbdt',False),('constant',False)]:
    oof[name]=np.empty(len(Y)); pp=[]; ff=[]
    x=features(train,inter); xt=features(test,inter)
    for a,b in splits:
        if name=='constant':
            pv=np.full(len(b),Y[a].mean()); pt=np.full(len(test),Y[a].mean())
        else:
            est=HistGradientBoostingClassifier(max_iter=100,max_leaf_nodes=15,random_state=40) if name=='gbdt' else LogisticRegression(max_iter=500)
            model=make_pipeline(preprocessor(inter),est).fit(x.iloc[a],Y[a])
            pv=model.predict_proba(x.iloc[b])[:,1]; pt=model.predict_proba(xt)[:,1]
        oof[name][b]=pv; pp.append(pt); ff.append(score(Y[b],pv)['logloss'])
    predictions[name]=np.mean(pp,axis=0); fold_scores[name]=ff
print(pd.DataFrame({k:score(Y,v) for k,v in oof.items()}).T)

40.6 TensorFlowによるニューラルネットワーク

MLPは数値・カテゴリ特徴を結合した入力から非線形関数を学習する。今回は小規模データなので64・32ユニットの2層とDropout、L2正則化を使う。出力は1ユニットのsigmoid。Adamで最適化する。入力の次元はFold内のOne-hotカテゴリにより変わり得るため動的に決める。次のコードはTensorFlow環境で実行する。

コード40.5　MLPの構築
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

def build_mlp(dim, width=64, dropout=.2):
    model=keras.Sequential([keras.Input((dim,)),
        layers.Dense(width,activation='relu',kernel_initializer='he_normal',kernel_regularizer=keras.regularizers.l2(1e-4)),
        layers.Dropout(dropout),layers.Dense(width//2,activation='relu'),
        layers.Dense(1,activation='sigmoid')])
    model.compile(optimizer=keras.optimizers.Adam(1e-3),loss='binary_crossentropy')
    return model

40.7 交差検証と学習の改善

外側FoldをEarly Stoppingに使うと、そのFoldのラベルで学習時期を選ぶことになる。そこで外側訓練部分を設備単位でさらに分割し、内側検証で最適エポックを選択する。その後、外側訓練全体で前処理とモデルを新規学習し、外側検証を一度だけ予測する。比較候補は幅64・128の2種類と事前に定める。候補選択後のOOFは楽観的になり得るため、独立ホールドアウトを最後に評価する。

コード40.6　設備単位の内側検証とMLPのOOF学習
for width in [64,128]:
    name=f'mlp{width}'; oof[name]=np.empty(len(Y)); pp=[]; ff=[]
    x=features(train); xt=features(test)
    for fold,(a,b) in enumerate(splits):
        ii,jj=next(GroupShuffleSplit(n_splits=1,test_size=.2,random_state=40+fold).split(x.iloc[a],Y[a],train.group.iloc[a]))
        ia,iv=a[ii],a[jj]
        keras.backend.clear_session(); keras.utils.set_random_seed(40+fold)
        prep=preprocessor().fit(x.iloc[ia])
        model=build_mlp(prep.transform(x.iloc[ia]).shape[1],width)
        hist=model.fit(prep.transform(x.iloc[ia]),Y[ia],validation_data=(prep.transform(x.iloc[iv]),Y[iv]),epochs=60,batch_size=64,verbose=0,callbacks=[keras.callbacks.EarlyStopping(monitor='val_loss',patience=6)])
        epochs=int(np.argmin(hist.history['val_loss']))+1
        keras.backend.clear_session(); keras.utils.set_random_seed(40+fold)
        prep=preprocessor().fit(x.iloc[a]); xa=prep.transform(x.iloc[a])
        model=build_mlp(xa.shape[1],width)
        model.fit(xa,Y[a],epochs=epochs,batch_size=64,verbose=0)
        pv=model.predict(prep.transform(x.iloc[b]),verbose=0).ravel()
        pt=model.predict(prep.transform(xt),verbose=0).ravel()
        oof[name][b]=pv; pp.append(pt); ff.append(score(Y[b],pv)['logloss'])
    predictions[name]=np.mean(pp,axis=0); fold_scores[name]=ff
    print(name,score(Y,oof[name]))

40.8 誤差分析とアブレーション

モデル間の差だけでなく、どの標本で誤るかを調べる。交互作用の有無は線形モデルのアブレーションに相当する。欠損あり・なしで損失を集計し、件数も併記する。ここでは改善候補を固定しているが、追加特徴を発見した場合は最終テストではなく訓練データ内で再検証する。

コード40.7　標本別誤差とFoldのばらつき
pr=np.clip(oof['gbdt'],1e-7,1-1e-7)
loss=-Y*np.log(pr)-(1-Y)*np.log1p(-pr)
err=pd.DataFrame({'loss':loss,'missing':features(train).isna().any(axis=1)})

40.9 アンサンブルとモデル選択

異なるモデルは異なる誤差を持つ。事前に固定した等重み平均は、重みを検証データで最適化する場合より自由度が少ない。ただし平均するモデルの選択による過適合は起こり得る。

$$p_{\mathrm{blend}}=\frac{p_1+p_2}{2}$$

交互作用付き線形モデルとGBDTの平均、およびMLPが実行済みならGBDTとMLP64の平均を追加する。主指標のOOF Log Lossが最小の候補を採用する規則を事前に固定する。OOFで最良だった値は最終性能の不偏推定とは限らない。またOOFは各行を除外した1モデルの予測であり、Fold平均のテスト予測と同一の推論方式ではない。

コード40.8　アンサンブルと候補選択
pairs=[('interaction','gbdt')]
if 'mlp64' in oof: pairs.append(('mlp64','gbdt'))
for a,b in pairs:
    name=a+'+'+b
    oof[name]=(oof[a]+oof[b])/2
    predictions[name]=(predictions[a]+predictions[b])/2
scores={k:score(Y,v) for k,v in oof.items()}
selected=min(scores,key=lambda k:scores[k]['logloss'])
print(pd.DataFrame(scores).T.sort_values('logloss'))
print('Selected:',selected)

40.12 総合課題と本編のまとめ

本編では数学、学習原理、実装、最適化、各種モデル、タスク別実践、応用技術、コンペ戦略を学んだ。総合演習ではこれらを一つの再現可能な実験へ接続した。次の課題では、変更点を一つずつ記録し、評価条件を揃え、最終テストをモデル選択に使わないこと。

問1　設備IDを特徴量から除く理由は？

未知設備への汎化を目的とするため。

問2　GroupKFoldの目的は？

同一設備が訓練と検証に混在しないようにする。

問3　欠損補完をFold内で学ぶ理由は？

検証情報の混入を防ぐ。

問4　Log LossとAUCは何が違う？

前者は確率の質、後者は順位識別を評価する。

問5　内側検証で選ぶものは？

本演習では学習エポック数。

問6　OOF最良値が楽観的になる理由は？

複数候補から同じOOFで選択したため。

問7　提出順が異なる場合は？

IDで照合する。

問8　発展：欠損指標の有無を比較せよ。

コード40.3の数値補完器のadd_indicatorをFalseにした前処理を別途定義し、同じFold・交互作用付きロジスティック回帰でOOF Log Lossを比較する。カテゴリ欠損の処理は固定し、模擬テストは選択に使わない。再計算例：欠損指標あり0.565076、なし0.564831。

問9　総合課題：実コンペに移行せよ。

規約・指標・分割を再設計し、ベースラインから提出検査まで再現可能に実行する。

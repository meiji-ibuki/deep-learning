14.1 LayerとModel：モデル構築の基本単位

第12章で作ったDenseやSequentialのクラスを思い出してください。Kerasでは、Layerが計算と状態（重みなど）を管理し、Modelがレイヤーをまとめて一つの予測器にします。ModelもLayerの一種なので、別のモデルの内部に組み込むことができます。本章ではTensorFlow 2系・Keras 3のTensorFlowバックエンドを使用し、tf.keras に統一します。コードは同じNotebookで上から順に実行してください。

Dense層は第8章の $Z=XW+b$ と活性化関数を実装しています。入力の最後の軸が4、出力幅が8なら重みは(4,8)、バイアスは(8,)です。バッチサイズBはパラメータ数に影響しません。

コード14.1　環境とレイヤーの状態を確認する
import numpy as np
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

keras.utils.set_random_seed(42)
x = tf.ones((2, 4))
dense = layers.Dense(8, activation="relu")
y = dense(x)  # 初回呼び出しで重みを作成
print(y.shape)  # (2, 8)
print(dense.kernel.shape, dense.bias.shape)
print(dense.count_params())  # 40

レイヤーを生成しただけでは入力幅が未確定で、重みがまだ存在しない場合があります。入力を与えるかbuildで形状を決めると重みが作られます。trainable_weightsは通常の勾配による最適化対象、non_trainable_weightsは別の方法で更新される状態や凍結された重みなどです。後者にもBatchNormalizationの移動統計量のように学習時に更新されるものがあります。

14.2 Sequential API：直列のモデル

入力から出力まで一本道であればSequentialが最も簡潔です。Inputのshapeにはバッチ軸を含めません。例えば4特徴量から3クラスを分類するMLPを構築します。出力はロジットとし、損失にはfrom_logits=Trueを指定します（第10章）。

コード14.2　Sequentialで分類モデルを構築する
seq = keras.Sequential([
    keras.Input(shape=(4,), name="features"),
    layers.Dense(8, activation="relu", name="hidden"),
    layers.Dense(3, name="logits"),
], name="sequential_mlp")
seq.summary()
assert seq.count_params() == 67
print(seq(x).shape)  # (2, 3)
層出力shapeパラメータ数
Input(B,4)0
Dense(8)(B,8)4×8+8=40
Dense(3)(B,3)8×3+3=27
合計—67

add()で末尾にレイヤーを追加し、pop()で削除することもできます。ただし学習済みモデルの構造を変更した場合は、学習設定やオプティマイザの状態を見直します。分岐・複数入力・複数出力を表すには次節のFunctional APIが自然です。

14.3 Functional API：計算グラフを組み立てる

Functional APIでは、入力から各レイヤーを呼び出して接続し、最後に入力と出力を指定します。Inputが返すKerasTensorは具体的なデータではなく、shapeやdtypeを持つ記号的なテンソルです。実データを渡すとグラフの計算が実行されます。

コード14.3　同じMLPをFunctional APIで構築する
inp = keras.Input(shape=(4,), name="features")
h = layers.Dense(8, activation="relu", name="hidden")(inp)
out = layers.Dense(3, name="logits")(h)
func = keras.Model(inputs=inp, outputs=out, name="functional_mlp")
func.set_weights(seq.get_weights())
np.testing.assert_allclose(seq(x).numpy(), func(x).numpy(), atol=1e-6)
print(func.count_params())  # 67

同じ構造でも初期値が異なれば、一般に出力は一致しません。ここでは重みとバイアスをコピーして、APIの違いが計算の違いではないことを確認します。Keras 3ではFunctionalモデルの構築時に記号的なKerasTensorを直接TensorFlowの関数へ渡すことはできません。モデル構築時はkeras.opsやKerasレイヤーを使い、必要なら独自Layerのcall内にTensorFlow演算を記述します。

14.4 分岐・結合・残差接続

Functional APIの利点は、同じ入力から複数の経路を作り、それらを再結合できることです。Concatenateは指定軸に沿って特徴を連結し、Addは対応する要素を加算します。

コード14.4　分岐した特徴を連結する
inp = keras.Input(shape=(4,))
a = layers.Dense(8, activation="relu")(inp)
b = layers.Dense(6, activation="tanh")(inp)
h = layers.Concatenate(axis=-1)([a, b])
branch = keras.Model(inp, h)
assert branch(x).shape == (2, 14)

残差接続は入力を変換した結果F(x)に元の入力xを加える構造です。第11章の分岐した計算グラフの考え方が使われます。出力幅が異なる場合は射影用Denseなどで形状を合わせます。残差接続の効果は第25章で詳しく扱います。

コード14.5　残差ブロックを組み立てる
inp = keras.Input(shape=(8,))
h = layers.Dense(8, activation="relu")(inp)
h = layers.Dense(8)(h)
out = layers.Add()([inp, h])
residual = keras.Model(inp, out)
assert residual(tf.ones((2, 8))).shape == (2, 8)

14.5 複数入力モデル：異なる情報を統合する

住宅価格予測を例に、面積・築年数などの数値特徴と、地域などのカテゴリIDを別々の入力として扱います。Embeddingは整数IDを学習可能なベクトルに変換する層です。カテゴリIDの大小に意味がない場合に有用です。未知カテゴリ用IDを予約し、語彙や前処理は訓練データだけで決めます（第16章）。

コード14.6　辞書形式の入力を持つ回帰モデル
num = keras.Input(shape=(4,), name="numeric")
region = keras.Input(shape=(1,), dtype="int32", name="region")
a = layers.Dense(8, activation="relu")(num)
b = layers.Embedding(input_dim=6, output_dim=3)(region)
b = layers.Flatten()(b)
h = layers.Concatenate()([a, b])
price = layers.Dense(1, name="price")(h)
price_model = keras.Model({"numeric": num, "region": region}, price)
features = {"numeric": tf.ones((2, 4)),
            "region": tf.constant([[1], [5]], dtype=tf.int32)}
assert price_model(features).shape == (2, 1)
assert price_model.count_params() == 70

入力名を辞書のキーと一致させると、複数入力の順番を取り違える事故を防げます。Embeddingのinput_dim=6は有効な非負整数ID 0〜5を表し、出力shapeは(B,1,3)です。Flattenで(B,3)に変換しています。パラメータ数は数値側40、Embedding 18、出力層12の計70です。

14.6 複数出力モデル：マルチタスク学習

共通の特徴表現から異なるタスクの予測を行う方法をマルチタスク学習と呼びます。例えば住宅価格の回帰と、高価格帯か否かの二値分類を同時に学習させます。補助タスクが有用な表現の学習を促す可能性がありますが、タスク間の競合によって性能が悪化する場合もあります。

$$J=\lambda_1 J_{\mathrm{price}}+\lambda_2 J_{\mathrm{class}}$$

共有層では両タスクから戻る勾配が損失の係数に従って加算されます。正則化損失があれば、それも全体の損失に加わります。loss_weightsは損失の係数であり、各損失の数値スケールも考慮して決める必要があります。次の例では価格を標準化した値として扱う想定です。

コード14.7　複数出力と損失の設定
inp = keras.Input(shape=(4,))
h = layers.Dense(16, activation="relu")(inp)
price = layers.Dense(1, name="price")(h)
expensive = layers.Dense(1, name="expensive")(h)
multitask = keras.Model(inp, {"price": price, "expensive": expensive})
multitask.compile(
    optimizer="adam",
    loss={"price": "mse", "expensive": keras.losses.BinaryCrossentropy(from_logits=True)},
    loss_weights={"price": 1.0, "expensive": 0.5},
    metrics={"price": ["mae"], "expensive": [keras.metrics.BinaryAccuracy(threshold=0.0)]},
)
labels = {"price": np.array([[0.2], [-0.3]], dtype="float32"),
          "expensive": np.array([[1.], [0.]], dtype="float32")}
print(multitask.train_on_batch(x, labels, return_dict=True))

ロジットに対するBinaryAccuracyでは閾値0.0を使います。確率に変換して評価する場合は通常0.5です。KerasのBinaryAccuracyは閾値を厳密に上回る場合に1と判定します。学習・検証・テストの分割は標本単位でそろえ、各タスクの正解を対応させます。

14.7 レイヤー共有とモデルの再利用

同一のLayerインスタンスを複数回呼び出すと重みを共有します。別のインスタンスを作れば同じ設定であっても別の重みを持ちます。例えば二つのベクトルを同一の変換で比較するモデルを考えます。

コード14.8　重み共有と中間モデルの抽出
a = keras.Input(shape=(4,), name="a")
b = keras.Input(shape=(4,), name="b")
shared = layers.Dense(8, activation="relu")
shared_model = keras.Model([a, b], [shared(a), shared(b)])
assert shared_model.count_params() == 40  # 80ではない
encoder = keras.Model(func.inputs, func.get_layer("hidden").output)
assert encoder(x).shape == (2, 8)
# encoderはfuncのhidden層と重みを共有する

中間出力を取り出すモデルは特徴抽出やデバッグに有用です。重み共有はメモリやパラメータ数を減らしますが、呼び出しごとの演算は必要です。抽出モデルを学習すれば元モデルの共有重みも変化する点に注意します。

14.8 Model Subclassing：処理をクラスとして定義する

Modelを継承してcall()に順伝播を記述する方法です。第12章のスクラッチ実装に似ていますが、Kerasが状態管理と自動微分を担います。レイヤーは通常__init__で定義し、callで呼び出します。入力shapeに依存する独自の重みはbuildでadd_weightを使って生成します。callのたびに新しいDenseを生成してはいけません。

コード14.9　Subclassingで同じMLPを構築する
class MLP(keras.Model):
    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        self.hidden = layers.Dense(8, activation="relu")
        self.head = layers.Dense(3)

    def call(self, inputs, training=False):
        h = self.hidden(inputs)
        return self.head(h)

sub = MLP(name="subclass_mlp")
_ = sub(x)  # 初回呼び出しでbuild
sub.set_weights(seq.get_weights())
np.testing.assert_allclose(seq(x).numpy(), sub(x).numpy(), atol=1e-6)
assert sub.count_params() == 67

trainingは学習時と推論時で振る舞いが異なるレイヤーへ渡します。例えばDropoutは学習時のみ一部の要素を無効化します（第20章）。BatchNormalizationもtrainingに依存します。モデルを直接呼び出す際にはtraining=Falseを明示すると意図が明確になります。

コード14.10　trainingフラグを伝える
class DropoutMLP(keras.Model):
    def __init__(self):
        super().__init__()
        self.dense = layers.Dense(8, activation="relu")
        self.drop = layers.Dropout(0.5)
        self.head = layers.Dense(3)

    def call(self, inputs, training=False):
        h = self.dense(inputs)
        h = self.drop(h, training=training)
        return self.head(h)

m = DropoutMLP()
p1 = m(x, training=False)
p2 = m(x, training=False)
np.testing.assert_allclose(p1.numpy(), p2.numpy())

14.9 モデルの検査・可視化とAPIの選択

モデルを構築したらまず少量のダミー入力を通し、出力shape、パラメータ数、値の有限性を確認します。summaryは各層の情報を表示し、Functionalモデルでは接続情報も確認できます。plot_modelはモデル構造を画像化しますが、pydotとGraphvizの実行環境が必要です。Subclassingの任意のPython制御フローは完全なグラフとして可視化できないことがあります。

コード14.11　モデルの検査と構造の可視化
func.summary()
for w in func.weights:
    print(w.path, w.shape, w.dtype)
tf.debugging.assert_shapes([(func(x), (2, 3))])
tf.debugging.assert_all_finite(func(x), "invalid logits")
# pydotとGraphvizが利用可能な環境で実行
# keras.utils.plot_model(func, to_file="model.png",
#                        show_shapes=True, show_layer_names=True)
比較項目SequentialFunctionalSubclassing
構造直列有向非巡回グラフcallで記述
複数入力・出力原則不可対応対応
構造の検査容易容易制約あり
自由度低高非常に高い
保存標準的な構成なら容易標準的な構成なら容易独自クラスの復元設定に注意

KaggleではまずSequentialでベースラインを作り、分岐や複数入力が必要ならFunctionalを選ぶのが実践的です。独自の制御フローや再利用する複雑な処理が必要ならSubclassingを検討します。標準APIだけで表現できるなら、読みやすさと検証の容易さを優先しましょう。Keras 3のモデル保存には通常.keras形式を利用します。独自クラスの保存・復元やカスタムレイヤーは第15章・第17章で詳しく扱います。

14.10 実践：三種類のAPIで同じ分類器を学習する

アヤメデータセットを使い、三種類のAPIで同一の4→8→3モデルを比較します。ここで比較するのはAPIの表現方法であり、性能の優劣ではありません。初期重み、データ分割、標準化、オプティマイザの設定をそろえます。検証データで学習状況を確認し、テストは最後に一度だけ評価します。

コード14.12　データの準備と三つのモデルの学習
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
import matplotlib.pyplot as plt

X, y = load_iris(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=.2, stratify=y, random_state=42)
Xtr, Xva, ytr, yva = train_test_split(Xtr, ytr, test_size=.25, stratify=ytr, random_state=42)
scaler = StandardScaler().fit(Xtr)
Xtr, Xva, Xte = [scaler.transform(a).astype("float32") for a in (Xtr, Xva, Xte)]
initial = seq.get_weights()
histories = {}
for name, model in [("Sequential", seq), ("Functional", func), ("Subclassing", sub)]:
    model.set_weights(initial)
    model.compile(optimizer=keras.optimizers.Adam(0.01),
                  loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
                  metrics=["accuracy"])
    history = model.fit(Xtr, ytr, validation_data=(Xva, yva),
                        epochs=60, batch_size=16, shuffle=False, verbose=0)
    histories[name] = history.history
    print(name, model.evaluate(Xte, yte, verbose=0, return_dict=True))
for name, history in histories.items():
    plt.plot(range(1, len(history["val_loss"]) + 1), history["val_loss"], label=name)
plt.xlabel("Epoch")
plt.ylabel("Validation loss")
plt.legend()
plt.show()

shuffle=Falseは三つのAPIの比較条件を統一するための指定です。通常の訓練では適切にシャッフルします。各モデルに新しいAdamを生成し、オプティマイザの内部状態を共有しないようにしています。同じ計算でもデバイス・実行順・丸め誤差などにより結果が完全一致するとは限りません。グラフはコードを実行して確認してください。本章の制作環境ではTensorFlow学習実験は未実行です。

14.11 まとめと確認問題

Layerは計算と状態を管理し、Modelはそれらを組み合わせます。Sequentialは直列、Functionalは分岐や結合、Subclassingは独自の順伝播に適します。構造を変更したらshapeとパラメータ数を検証し、損失と出力の組み合わせも確認しましょう。

問1　Input(shape=(10,))に含まれない軸は？

バッチ軸。実際の入力は(B,10)。

問2　Dense(5)に10特徴量を入力する場合のパラメータ数は？

バイアスあり（既定）なら10×5+5=55。バイアスなしなら50。

問3　二つの入力を受け取るならどのAPIが自然か？

Functional API。Subclassingも可能。

問4　形状(B,8)と(B,6)を最後の軸で連結すると？

(B,14)。Addはこの形状のままでは使えない。

問5　同じDenseを二度呼ぶとパラメータ数は倍になるか？

同じインスタンスなら共有されるため倍にならない。

問6　call内で毎回Denseを生成してよいか？

通常は不可。状態は__init__またはbuildで作成する。

問7　ロジットの二値分類にBinaryAccuracyを使う閾値は？

通常0.0。確率なら0.5。

問8　モデルのAPI比較で初期重みをそろえる理由は？

ランダム初期化の違いを取り除き、同じ構造を異なるAPIで表現した場合の実装の違いを比較するため。

発展演習：射影付き残差ブロック

入力幅4、出力幅8の残差ブロックをFunctional APIで作ってください。主経路はDense(8, ReLU)→Dense(8)、短絡経路はDense(8)とし、加算後にReLUを適用します。パラメータ数も計算してください。

解答・実装例

主経路は40+72、短絡経路は40、合計152パラメータです。加算とReLUに学習パラメータはありません。

コード14.13　射影付き残差ブロック
inp = keras.Input(shape=(4,))
h = layers.Dense(8, activation="relu")(inp)
h = layers.Dense(8)(h)
skip = layers.Dense(8)(inp)
out = layers.Activation("relu")(layers.Add()([h, skip]))
projected = keras.Model(inp, out)
assert projected.count_params() == 152
assert projected(tf.ones((2, 4))).shape == (2, 8)

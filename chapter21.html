21.1 学習率とハイパーパラメータの役割

第18章では勾配をどのように更新方向へ変換するかを学んだ。本章では、その更新の尺度を制御する学習率（learning rate）と、学習前に決めるハイパーパラメータを考える。重み・バイアスはデータから勾配法で学ぶパラメータだが、学習率、層数、バッチサイズ、正則化係数などは通常、外側の探索によって決める。

$$\theta_{t+1}=\theta_t-\eta_t g_t$$

ここで $t$ は更新回数、$g_t$ は勾配、$\eta_t$ は学習率。Adamの場合は勾配を適応的に変換した方向に対して学習率が掛かる。学習率は実際の更新ノルムと同じではない。この更新式はSGDの基本形であり、MomentumやWeight Decayなどを含む場合は更新式が異なる。小さすぎると予算内に収束しにくく、大きすぎると振動や発散を起こす。

二次関数 $J(w)=aw^2/2$ では $w_t=w_0(1-a\eta)^t$ であり、$a>0$ のとき収束条件は $0<\eta<2/a$。一般の深層ネットでは曲率が場所によって変わるため、この条件をそのまま全体に適用できない。

21.2 学習率とバッチサイズ

標本数 $N$、バッチサイズ $B$ のとき、端数を含め、各バッチで1回更新する場合の1エポックの更新回数は $\lceil N/B\rceil$。同一パラメータで評価した勾配を独立に復元抽出するなら平均勾配の共分散は $\Sigma/B$ となる。バッチが大きいほど勾配ノイズは減るが、同じエポック数では更新回数も減る。

線形スケーリング則は、バッチを $k$ 倍にしたとき学習率も $k$ 倍にする経験則である。小さな更新の間で勾配がほぼ一定なら、$k$ 回の更新を1回で近似できるという考え方に基づく。ただし大規模バッチ、Adam、曲率が高い領域では成立する保証はない。平方根スケーリングも候補となる。Warmupと合わせ、実際に検証する。

21.3 基本的な学習率スケジューリング

スケジュールは事前に定めた規則で学習率を変える。初期には大きな更新で探索し、後半は小さな更新で調整するという設計が典型的である。

$$\eta_t=\eta_0\gamma^{\lfloor t/S\rfloor}\quad\text{(Step Decay)}$$ $$\eta_t=\eta_0\gamma^{t/S}\quad\text{(Exponential Decay)}$$ $$\eta_t=\eta_{\min}+(\eta_0-\eta_{\min})(1-t/T)^p\quad(0\le t\le T)$$

減衰では通常、$0<\gamma<1$、$S,T,p>0$、$0\le\eta_{\min}\le\eta_0$ とする。最後はPolynomial Decayで、$p=1$ は線形減衰。$S$ は減衰間隔、$T$ は予定更新回数。エポック単位とステップ単位を混同しない。予定を超えた場合の扱い（下限固定や再スタート）も定める。

コード21.1　基本スケジュールの計算
import numpy as np
t = np.arange(101)
base = .01
schedules = {
    'constant': np.full_like(t, base, dtype=float),
    'step': base * .5 ** (t // 25),
    'exponential': base * .5 ** (t / 25),
    'linear': .001 + .009 * (1-t/100),
}
assert np.isclose(schedules['step'][25], .005)

21.4 WarmupとCosine Annealing

Warmupは初期の学習率を小さくし、数ステップかけて目標値まで増やす。初期の不安定な勾配や大きな更新を抑える目的がある。Warmup期間 $W$ の後、余弦関数で滑らかに減衰する例は次のとおり。

$$\eta_t=\begin{cases}\eta_{\mathrm{start}}+(\eta_{\max}-\eta_{\mathrm{start}})t/W & 0\le t<W\\ \eta_{\min}+\frac{\eta_{\max}-\eta_{\min}}2\left[1+\cos\left(\pi\frac{t-W}{T-W}\right)\right]& W\le t\le T\end{cases}$$

$0<W<T$ を想定する。$t=W$ で最大値、$t=T$ で最小値となる。Warmupは必須ではなく、割合は総更新回数やモデルに応じて調整する。学習を早期終了すると予定した余弦減衰の末尾まで到達しない場合がある。

コード21.2　Warmup＋Cosineの境界値を検証
def warm_cos(t, total, warm, peak=.01, floor=.001):
    assert 0 < warm < total
    t = np.clip(np.asarray(t), 0, total)
    phase = np.clip((t-warm)/(total-warm), 0, 1)
    return np.where(t < warm, peak*t/warm,
        floor + .5*(peak-floor)*(1+np.cos(np.pi*phase)))
assert np.allclose(warm_cos([0,10,100],100,10), [0,.01,.001])

21.5 適応的な学習率制御と周期的スケジュール

事前に決めるスケジュールとは異なり、ReduceLROnPlateauは検証指標の改善が一定期間止まったときに学習率を下げる。factorは倍率、patienceは待機エポック数、min_deltaは改善判定幅、cooldownは減衰後の待機期間である。EarlyStoppingのpatienceは減衰後の改善を観察できるよう設定する。

周期的学習率（Cyclic LR）は上下限を周期的に往復する。Cosine Restartsは余弦減衰後に学習率を再上昇させる。One Cycleは学習率を一度上昇させてから低下させる方針で、Momentumも逆方向に調整する設計がある。いずれも万能ではなく最大学習率の設定が重要である。再スタートは通常、モデルの重みを初期化し直すことを意味しない。

21.6 Kerasによるスケジュールの実装

KerasのLearningRateScheduleはオプティマイザの更新ステップに基づいて評価される。バッチサイズ32、訓練標本600、50エポックなら端数バッチ込みで950ステップ。勾配累積や分散実行などでは実際の更新数を別途確認する。以下はTensorFlowバックエンドの例。

コード21.3　KerasのCosineDecayとWarmup（未実行）
import tensorflow as tf
from tensorflow import keras
import math
steps = math.ceil(600 / 32) * 50
warm = 50
schedule = keras.optimizers.schedules.CosineDecay(
    initial_learning_rate=1e-5,
    warmup_target=1e-3, warmup_steps=warm,
    decay_steps=steps-warm, alpha=.01)
optimizer = keras.optimizers.Adam(learning_rate=schedule)
print(float(schedule(0)), float(schedule(warm)), float(schedule(steps)))
コード21.4　検証損失に応じて減衰（未実行）
# 上の schedule とは別の実験で使う
optimizer = keras.optimizers.Adam(learning_rate=1e-3)

    keras.callbacks.ReduceLROnPlateau(monitor='val_loss', mode='min',

スケジュールオブジェクトを設定したオプティマイザに、学習率を代入するReduceLROnPlateauを同時に使わない。LearningRateSchedulerはエポック開始時に値を設定する別のコールバックである。学習再開ではoptimizer.iterationsとスケジュールの設定を確認する。

21.7 ハイパーパラメータ探索の基礎

ハイパーパラメータ探索は、設定 $h$ で訓練したモデル $\theta^*(h)$ の検証損失を最小化する外側の最適化と考えられる。

$$h^*=\arg\min_{h\in\mathcal H}J_{\mathrm{val}}(\theta^*(h))$$
探索法特徴注意
手動仮説を立てて一つずつ変更相互作用を見逃す
Grid Search候補の直積を全探索次元数とともに試行数が急増
Random Search分布から設定を抽出シードと予算を管理
Bayesian Optimization過去の試行結果から次の候補を選ぶ第36章で詳述
Successive Halving有望な試行へ予算を追加初期に伸びない候補を落とす可能性

学習率や正則化係数は桁単位で変化するため、対数一様分布が有用なことが多い。$u\sim U(a,b)$ として $\eta=10^u$ とする。層数やバッチサイズは離散候補から選ぶ。条件付き探索空間（Momentumを使う場合だけ係数を探索する等）も考慮する。

コード21.5　同一予算のGrid SearchとRandom Search
rng = np.random.default_rng(21)
grid = np.array([(a,b) for a in np.linspace(-5,-2,5)
                 for b in np.linspace(0,.5,5)])
random_points = np.column_stack([rng.uniform(-5,-2,25),
                                 rng.uniform(0,.5,25)])
assert len(grid) == len(random_points) == 25

21.8 NumPyによるスケジュール比較

同じ初期値と同じ更新予算で、曲率が異なる二次関数 $J(x,y)=(x^2+20y^2)/2$ を最小化する。ここでは勾配にノイズを加え、後半の学習率を下げる効果を調べる。最適点は原点。各手法に同一のノイズ系列を与えることで条件を統制する。

コード21.6　20試行の平均損失を比較（実行済み）
import numpy as np
rng = np.random.default_rng(21)
T = 200
t = np.arange(T)
noise = rng.normal(0, .5, (20,T,2))
rates = {
    'constant': np.full(T,.05),
    'step': .05 * .5 ** (t//50),
    'cosine': .001+.049*(1+np.cos(np.pi*t/T))/2,
}
results = {}
for name, rate in rates.items():
    w = np.full((20,2),3.)
    history = [np.mean(.5*np.sum(w*w*[1,20],axis=1))]
    for i, eta in enumerate(rate):
        w -= eta*(w*[1,20]+noise[:,i,:])
        history.append(np.mean(.5*np.sum(w*w*[1,20],axis=1)))
    results[name] = np.array(history)
    print(name, history[-1])
assert all(np.isfinite(v).all() for v in results.values())
スケジュール最終平均損失
constant0.0075046
step0.0014138
cosine0.0012740

減衰によって最適点付近のノイズによる揺れを抑えられる場合があるが、減衰が早すぎると最適点へ近づく前に更新が小さくなる。この実験は特定の二次関数とノイズ設定に限られ、ニューラルネットの汎化性能を保証しない。

21.9 実践：Kerasによる探索と比較

半月型データで学習率・バッチサイズ・Dropoutの組み合わせをランダム探索する。データ分割は固定し、標準化は訓練データだけで適応する。各候補を2シードで学習し、平均検証BCEで選ぶ。予算は最大30エポック×8候補×2シード。テストは選択後の固定シードのモデルに対してのみ行う。

コード21.7　ランダム探索の一貫した実装（TensorFlow未実行）
import numpy as np
import pandas as pd
import tensorflow as tf
from tensorflow import keras
from sklearn.datasets import make_moons
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
X,y = make_moons(n_samples=1200,noise=.25,random_state=21)
Xtr,Xtmp,ytr,ytmp = train_test_split(X,y,test_size=.4,
    stratify=y,random_state=21)
Xva,Xte,yva,yte = train_test_split(Xtmp,ytmp,test_size=.5,
    stratify=ytmp,random_state=21)
scaler = StandardScaler().fit(Xtr)
Xtr,Xva,Xte = [scaler.transform(a).astype('float32') for a in (Xtr,Xva,Xte)]
ytr,yva,yte = [a.astype('float32').reshape(-1,1) for a in (ytr,yva,yte)]
rng = np.random.default_rng(21)
configs = [(float(10**rng.uniform(-4,-2)),int(rng.choice([16,32,64])),
            float(rng.choice([0.,.1,.25]))) for _ in range(8)]
def make_model(lr,drop,seed):
    keras.utils.set_random_seed(seed)
    model = keras.Sequential([keras.Input((2,)),
        keras.layers.Dense(32,activation='relu'),keras.layers.Dropout(drop),
        keras.layers.Dense(16,activation='relu'),keras.layers.Dense(1)])
    model.compile(optimizer=keras.optimizers.Adam(lr),
        loss=keras.losses.BinaryCrossentropy(from_logits=True),
        metrics=[keras.metrics.BinaryAccuracy(threshold=0.)])
    return model
rows=[]
for i,(lr,b,drop) in enumerate(configs):
    for seed in (21,22):
        keras.backend.clear_session()
        model=make_model(lr,drop,seed)
        cb=keras.callbacks.EarlyStopping(monitor='val_loss',patience=6,
            restore_best_weights=True)
        model.fit(Xtr,ytr,batch_size=b,epochs=30,verbose=0,
            validation_data=(Xva,yva),callbacks=[cb])
        val=model.evaluate(Xva,yva,verbose=0,return_dict=True)['loss']
        rows.append(dict(trial=i,seed=seed,lr=lr,batch=b,drop=drop,val_loss=val))
        if seed==21: model.save(f'trial21_{i}.keras')
log=pd.DataFrame(rows)
log.to_csv('search21.csv',index=False)
summary=log.groupby('trial').val_loss.agg(['mean','std']).sort_values('mean')
best=int(summary.index[0])
model=keras.models.load_model(f'trial21_{best}.keras')
print(summary)
print('test',model.evaluate(Xte,yte,verbose=0,return_dict=True))

ここでは候補の平均検証損失を比較し、事前に決めたseed=21の保存モデルをテストする。最良シードを後から選ばない。バッチサイズが異なるので最大エポック数を固定しても更新回数は異なる。実行時間も記録すると実用上の比較がしやすい。モデルを実運用するなら標準化器と特徴量順序も保存する。

21.10 実験管理と選択の注意点

探索を始める前に評価指標、分割、予算、候補範囲を決める。まずベースラインを記録し、学習率を桁単位で試して発散しない範囲を見つけ、必要に応じてスケジュールを導入する。学習率範囲テスト（LR finder）は短い訓練中に学習率を増やして損失の変化を観察する方法だが、探索後は重みとオプティマイザ状態を元に戻すか新規に初期化する。

症状確認・対処
初期にNaN入力・損失・勾配を確認し学習率を下げる
損失がほぼ一定勾配と更新ノルムを確認。学習率が小さすぎないか調べる
後半で振動減衰やバッチサイズの調整を試す
訓練だけ改善正則化やデータ分割を見直す

試行を繰り返すと検証集合にも過適合する。小規模データでは交差検証、厳密な比較ではnested CVを検討する。Kaggleの公開Leaderboardを探索の主指標にしない。乱数シード、データ分割ID、バージョン、学習率の履歴、最良エポック、実行時間、成果物のパスを記録する。失敗試行も削除せず原因を残す。

21.11 まとめと確認問題

学習率は更新尺度、スケジュールは時間に応じた制御、ハイパーパラメータ探索は検証性能を使う外側の最適化である。目的に合う比較予算と独立した評価が重要となる。

N=1000、B=64の場合の更新回数は？

端数を含め16回。

曲率a=20の二次関数で収束する学習率は？

初期値が非ゼロの場合、0より大きく0.1未満。境界の0.1では符号が交互に変わるだけで収束しない。

Step Decayで初期0.01、倍率0.5、間隔10の場合、t=25の学習率は？

0.0025。

Warmupの目的は？

初期の過大な更新を抑えること。

Cosine Decayの最終値は？

予定した減衰の終点（t=T）では設定した最小学習率。最後の更新がt=T−1なら、その更新で使う値は一般に最小値より大きい。

対数一様探索の利点は？

複数の桁に同程度の探索予算を配分できる。

検証で最良のseedを選んでテストするべきか？

シードを後から選ぶと検証性能に選択バイアスが生じ得る。事前に決めたシードやアンサンブル方針を使う。独立テストを一度だけ用いるなら、その選択手続き込みの性能を評価できる。

バッチサイズを2倍にすれば学習率も必ず2倍か？

経験則にすぎないため検証が必要。

発展：ノイズ付き二次関数の減衰速度を比較せよ。

コードのstep間隔を25、50、100に変更し、同じノイズ系列で平均損失と最終損失を比較する。ノイズ標準偏差0と0.5でも比較する。 初期値を除く200更新後の損失の時間平均と最終平均損失の再計算例：σ=0, S=25: 平均=0.246235, 最終=0.0283766；σ=0, S=50: 平均=0.209806, 最終=0.000321706；σ=0, S=100: 平均=0.208277, 最終=9.97371e-07；σ=0.5, S=25: 平均=0.251964, 最終=0.0294656；σ=0.5, S=50: 平均=0.216457, 最終=0.00141383；σ=0.5, S=100: 平均=0.217457, 最終=0.00318091。

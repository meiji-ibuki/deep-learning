36.1 性能改善を実験として設計する

第21章では学習率や探索の基本を扱った。本章ではモデル改善を仮説検証の反復として設計する。スコアが低いとき、モデル容量を増やす前に、評価分割・ラベル品質・前処理・損失関数が目的に合うかを確認する。変更前のベースラインを固定し、一度に何を変えたかを記録する。

訓練も検証も悪い場合は容量不足、最適化不良、特徴不足が候補になる。訓練のみ良い場合は過学習や分布差を疑う。ただし学習曲線だけでは原因は確定しない。第23章の診断と組み合わせよう。

36.2 探索の数学的定式化と評価の独立性

重み $w$ とハイパーパラメータ $\lambda$ を区別する。学習は内側の最適化、探索は外側の最適化である。

$$w^*(\lambda)=\arg\min_w L_{train}(w;\lambda),\qquad \lambda^*=\arg\min_{\lambda\in\Lambda}L_{val}(w^*(\lambda))$$

実際には有限回の学習で得る近似解を使う。検証スコアは分割や初期値に依存する。多数の試行の最小値を選ぶと偶然良かった候補を選びやすい（選択バイアス）。独立テストは選択終了後に一度評価し、交差検証で探索自体の性能を推定するときはNested CVを用いる。KaggleのPublic LBも繰り返し参照すると過適合し得る。

36.3 探索空間の設計

探索空間 $\Lambda$ は連続値・整数・カテゴリ・条件付き変数を含む。学習率やweight decayは桁単位で効果が変わるため対数一様分布を使うことが多い。$u\sim U(\log a,\log b)$ として $\eta=\exp u$ とすれば、密度は $0<a<b$ のとき、$a\leq\eta\leq b$ で $p(\eta)=1/(\eta\log(b/a))$、範囲外では0となる。

変数探索例考え方
学習率1e-5〜1e-2（log）桁単位
層数1〜3整数
幅32,64,128,256離散
Dropout0〜0.5線形
OptimizerAdam, SGD条件付きでmomentum等

範囲は普遍的な推奨値ではなく出発点。OOMを招く構成や不可能な組合せは除外する。探索の結果が境界に集中すれば範囲を見直す。探索の途中で評価条件を変えない。

36.4 Grid SearchとRandom Search

Grid Searchは各軸の候補の直積を全て評価する。各軸に $k$ 候補、$d$ 次元なら $k^d$ 試行となる。Random Searchは分布から独立に候補を抽出する。重要な軸が少ないとき、同じ試行数でも重要な軸を広く探索できる。良い領域の確率質量が $p$ なら、$n$ 独立試行で少なくとも一度当たる確率は $1-(1-p)^n$ である。

次の人工目的関数では第一軸の寄与が第二軸より大きく、実際の学習性能を表すものではない。16試行のGridとRandomを200シードで比較する。

コード36.1　探索予算を固定した比較
import numpy as np
from itertools import product

def objective(x):
    return (x[...,0]-.37)**2 + .001*(x[...,1]-.8)**2
grid=np.array(list(product(np.linspace(0,1,4),repeat=2)))
grid_best=objective(grid).min()
random_best=np.array([objective(np.random.default_rng(s).random((16,2))).min()
                      for s in range(200)])
print(grid_best, np.median(random_best))

Gridの最良値は0.001362、Randomの中央値は0.000860。これは関数と探索範囲に依存し、Randomが常に優れる証拠ではない。

36.5 ベイズ最適化とTPE

ベイズ最適化は観測済みの試行から目的関数の代理モデルを作り、次の候補を選ぶ。ガウス過程では予測平均 $\mu(x)$ と不確実性 $\sigma(x)$ を利用できる。最小化で現在の最良値を $f^*$ とすると、Expected Improvementは

$$EI(x)=E[\max(f^*-F(x),0)]$$

正規予測分布なら $z=(f^*-\mu)/\sigma$ として $EI=(f^*-\mu)\Phi(z)+\sigma\phi(z)$（$\sigma>0$）。両項の和が改善量の期待値を表す。第一項は負にもなり得るため、個別に非負の改善量とは解釈しない。$\sigma=0$ では $EI=\max(f^*-\mu,0)$ となる。探索と活用のバランスが重要である。

TPEは目的値の良い試行と残りの試行に分け、パラメータの密度 $l(x)=p(x\mid y<y^*)$、$g(x)=p(x\mid y\ge y^*)$ を推定する。典型的には $l(x)/g(x)$ が大きい候補を選ぶ。条件付き空間にも適する。初期の観測が少ない間はランダムな探索も必要になる。OptunaのTPESamplerとKerasTunerのBayesianOptimizationは同じアルゴリズムではない。

36.6 Successive Halving・Hyperband・枝刈り

全候補を最後まで学習する必要はない。Successive Halvingでは多数の候補に少量の資源を割り当て、成績上位だけに次段階の資源を配る。Hyperbandは初期候補数と初期資源量の異なる複数の構成を組み合わせる。Median Prunerは途中経過を過去の試行と比較する。Early Stoppingは個々のモデルの過学習抑制、pruningは探索予算の配分という目的の違いがある。

序盤の成績が悪く後半に伸びる構成を切り捨てる危険がある。Warmupを考慮し、最低エポック数を設定する。比較する資源がエポックなのか更新回数なのかも明確にする。異なるバッチサイズでは同じエポック数でも更新回数が異なる。

36.7 実践：データとベースライン

実習はscikit-learn付属の手書き数字データを利用する。64画素を入力とする10クラス分類で、外部データは不要。訓練・検証・テストを層化分割し、固定の検証集合を探索に使用する。画素値の既知の上限16で割るので訓練統計の漏洩はない。コード36.2でデータを準備し、コード36.3でモデル関数を定義する。コード36.4〜36.5は両方に依存する。OptunaとKerasTunerは別々の探索例であり、両方実行した場合はテストを見る前に選択を終える。

コード36.2　共通データ分割とモデル関数
import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
X,y=load_digits(return_X_y=True)
X=X.astype('float32')/16
Xdev,Xtest,ydev,ytest=train_test_split(X,y,test_size=.2,stratify=y,random_state=36)
Xtr,Xval,ytr,yval=train_test_split(Xdev,ydev,test_size=.25,stratify=ydev,random_state=36)
baseline=LogisticRegression(max_iter=1000).fit(Xtr,ytr)
print('Baseline val accuracy:',baseline.score(Xval,yval))
コード36.3　Kerasモデルと学習関数
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

def build(width=64, depth=2, dropout=.2, lr=.001):
    model=keras.Sequential([keras.Input((64,))])
    for _ in range(depth):
        model.add(layers.Dense(width,activation='relu'))
        model.add(layers.Dropout(dropout))
    model.add(layers.Dense(10))
    model.compile(optimizer=keras.optimizers.Adam(lr),
        loss=keras.losses.SparseCategoricalCrossentropy(from_logits=True),
        metrics=['accuracy'])
    return model
keras.utils.set_random_seed(36)
model=build()
h=model.fit(Xtr,ytr,validation_data=(Xval,yval),epochs=30,batch_size=32,
    callbacks=[keras.callbacks.EarlyStopping(monitor='val_loss',patience=5,
                                            restore_best_weights=True)],verbose=0)
print(model.evaluate(Xval,yval,verbose=0))

36.8 実践：Optunaによる探索

OptunaはStudyの中でTrialを実行する。目的値は検証損失の最小値とする。各候補を同じ初期シードで独立に構築し、途中の検証損失を報告する。以下は pip install optuna が必要。探索後は上位候補を別シードで再評価するのが望ましい。

コード36.4　TPEとMedianPruner
import optuna
class PruneCallback(keras.callbacks.Callback):
    def __init__(self,trial):
        super().__init__(); self.trial=trial
    def on_epoch_end(self,epoch,logs=None):
        self.trial.report(float(logs['val_loss']),step=epoch)
        if self.trial.should_prune():
            raise optuna.TrialPruned()

def objective(trial):
    keras.backend.clear_session()
    keras.utils.set_random_seed(36)
    params=dict(width=trial.suggest_categorical('width',[32,64,128]),
                depth=trial.suggest_int('depth',1,3),
                dropout=trial.suggest_float('dropout',0,.5),
                lr=trial.suggest_float('lr',1e-4,1e-2,log=True))
    m=build(**params)
    h=m.fit(Xtr,ytr,validation_data=(Xval,yval),epochs=30,batch_size=32,
            callbacks=[PruneCallback(trial)],verbose=0)
    trial.set_user_attr('best_epoch',int(np.argmin(h.history['val_loss']))+1)
    return min(h.history['val_loss'])
study=optuna.create_study(direction='minimize',
    sampler=optuna.samplers.TPESampler(seed=36),
    pruner=optuna.pruners.MedianPruner(n_startup_trials=5,n_warmup_steps=5))
study.optimize(objective,n_trials=20)
print(study.best_params,study.best_value)
study.trials_dataframe().to_csv('trials36.csv',index=False)

36.9 実践：KerasTunerによる探索

KerasTunerではHyperModelを関数として定義し、Tunerが候補を生成・評価する。以下はpip install keras-tuner が必要。BayesianOptimizationを採用するが、RandomSearchやHyperbandも利用できる。探索ディレクトリを分け、overwrite=Trueは既存探索を上書きする点に注意する。

コード36.5　KerasTunerによるベイズ最適化
import keras_tuner as kt

def hypermodel(hp):
    return build(width=hp.Choice('width',[32,64,128]),
                 depth=hp.Int('depth',1,3),
                 dropout=hp.Float('dropout',0,.5),
                 lr=hp.Float('lr',1e-4,1e-2,sampling='log'))
tuner=kt.BayesianOptimization(hypermodel,objective='val_loss',
    max_trials=20,seed=36,directory='tuning36',project_name='digits',overwrite=True)
tuner.search(Xtr,ytr,validation_data=(Xval,yval),epochs=30,batch_size=32,
    callbacks=[keras.callbacks.EarlyStopping(monitor='val_loss',patience=5)],verbose=0)
print(tuner.get_best_hyperparameters(1)[0].values)
# 探索終了後に上位候補を再学習し、検証集合で選択する。独立テストは保留する。
コード36.6　Optuna上位候補の再評価と最終学習（コード36.2〜36.4の後に実行）
from optuna.trial import TrialState
completed=sorted([t for t in study.trials if t.state==TrialState.COMPLETE],
                 key=lambda t:t.value)[:3]
if not completed:
    raise RuntimeError("No completed trials")
results=[]
for t in completed:
    vals=[]; epochs=[]
    for seed in [37,38,39]:
        keras.backend.clear_session(); keras.utils.set_random_seed(seed)
        m=build(**t.params)
        h=m.fit(Xtr,ytr,validation_data=(Xval,yval),epochs=30,batch_size=32,verbose=0)
        vals.append(min(h.history['val_loss']))
        epochs.append(int(np.argmin(h.history['val_loss']))+1)
    results.append((np.mean(vals),t.params,int(np.median(epochs))))
_,params,n_epochs=min(results,key=lambda r:r[0])
keras.backend.clear_session(); keras.utils.set_random_seed(40)
final=build(**params)
final.fit(Xdev,ydev,epochs=n_epochs,batch_size=32,verbose=0)
# ここで選択を終了し、テストは一度だけ評価する。
print(final.evaluate(Xtest,ytest,verbose=0))
final.save('digits36.keras')

この例ではシードを変えても検証集合は共通なので、選択バイアスは残る。最終テストはその影響を受けないよう保留する。より厳密な性能推定にはNested CVを使う。再学習時に訓練集合が増えると最適エポックが変わる可能性がある。

36.10 誤差分析とアブレーション

スコアだけでは何を改善すべきか分からない。OOF予測や検証予測をクラス・入力品質・グループなどで分け、各群の件数と指標を確認する。誤分類が多い群を人手で点検し、ラベル誤り、情報不足、分布差を区別する。テスト集合を改善の材料にしてはいけない。

アブレーションは基準構成から一要素を除去・追加して寄与を調べる。同じFold・シード・予算で対比較する。要素間の相互作用があるので、単独で効かなかった要素が組合せで効く場合もある。

コード36.7　検証集合のクラス別誤差分析
from sklearn.metrics import confusion_matrix,classification_report
pred=baseline.predict(Xval)
cm=confusion_matrix(yval,pred,labels=np.arange(10))
print(classification_report(yval,pred,zero_division=0))
recall=np.divide(np.diag(cm),cm.sum(axis=1),out=np.full(10,np.nan),where=cm.sum(axis=1)!=0)
print('Worst recall class:',np.nanargmin(recall))
コード36.8　アブレーションの対比較（線形モデルの例）
from sklearn.model_selection import StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import log_loss
folds=StratifiedKFold(5,shuffle=True,random_state=36)
paired=[]
for tr,va in folds.split(Xdev,ydev):
    row=[]
    for m in [LogisticRegression(max_iter=1000),
              make_pipeline(StandardScaler(),LogisticRegression(max_iter=1000))]:
        m.fit(Xdev[tr],ydev[tr]); row.append(log_loss(ydev[va],m.predict_proba(Xdev[va])))
    paired.append(row)
paired=np.array(paired)
print('Scaled minus baseline:',paired[:,1]-paired[:,0])

Fold間の訓練データは重複するため、この5個の差を独立標本として単純な信頼区間に変換しない。平均とばらつきは記述的に扱う。また、この実験は開発データだけで行う。

36.11 実験管理・再現性・計算予算

計算予算を試行数だけでなくGPU時間・更新回数・メモリでも管理する。安価なモデルで探索範囲を絞り、上位候補を本番サイズで確認する。縮小モデルでの順位が本番でも維持される保証はない。探索中のモデルは必要に応じて保存し、失敗した試行も記録する。

記録対象内容
データ版、分割ID、前処理、特徴量
構成全ハイパーパラメータ、シード、コード版
結果Foldごとの指標、学習曲線、OOF、時間、失敗理由
環境Python、TensorFlow、GPU、依存版

TensorBoard、MLflow、Weights & Biasesなどは記録の選択肢である。まずCSVと設定JSONでも十分に開始できる。GPUの非決定的な演算や環境差により、同一シードでも完全一致しないことがある。

36.12 まとめと確認問題

性能改善は探索手法だけでなく、独立した評価、適切な探索空間、誤差分析、再現性の組合せで決まる。最初はRandom Searchを基準とし、計算予算に応じてTPE・ベイズ最適化・枝刈りを導入する。次章では複数モデルの予測を組み合わせる。

問1　重みとハイパーパラメータの違いは？

重みは学習で更新し、ハイパーパラメータは学習条件として外側で選ぶ。

問2　学習率を対数一様で探索する理由は？

各桁を同程度に探索するため。

問3　Gridの試行数は各軸5候補で4次元なら？

625試行。

問4　EIで不確実性を考慮する理由は？

未探索領域により良い値がある可能性を評価するため。

問5　TPEのl/gは何を意味するか？

良い試行で現れやすく悪い試行で現れにくい候補を優先する。

問6　枝刈りの危険は？

後半で改善する候補を早期に除外し得る。

問7　テストスコアで探索してはいけない理由は？

最終評価の独立性が失われる。

問8　アブレーションで固定すべきものは？

分割、シード、評価指標、予算など。

問9　発展：予算20試行の探索を設計せよ。

例えば20探索試行のうち初期5試行をランダム、残り15試行をTPEとし、最大30エポック、最初の5エポックは枝刈りしない。検証損失で上位3候補を選び、別シードで再評価する。再評価9学習と最終学習1回は20探索試行とは別予算として明記し、独立テストは選択終了後に一度だけ評価する。

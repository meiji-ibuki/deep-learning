17.1 標準機能を拡張するということ

第14〜16章ではモデルを構築し、compileとfitを使い、データを供給しました。標準の学習処理で表現できない計算が必要な場合、Kerasでは必要な部分だけを置き換えられます。たとえばコンペの評価指標が独自の誤差であればMetricを追加し、学習時にだけ補助損失を加えたいならLayerやModelを拡張します。

重要なのは、変更したい責務だけを変更することです。すべてを手書きにすると、評価の集約や保存、分散学習などの責任まで自分で負うことになります。本章ではTensorFlowバックエンドのKeras 3、単一デバイス・float32を前提とします。コード17.1以降は順番に実行してください。

17.2 カスタムレイヤーと学習可能な重み

Layerは計算と状態をまとめる単位です。入力の幅に依存しない設定は__init__、入力の形状に依存する重みはbuild、順伝播はcallに記述します。第12章のDenseクラスと異なり、逆伝播はTensorFlowが担当します。

$$Y=XW+b$$

入力が $(B,d)$、出力幅が $h$ なら、重みは $(d,h)$、バイアスは $(h,)$ です。Keras 3では追跡される重みを作るためにadd_weightを使います。単なるtf.Variableを属性に代入するだけではKerasの重みとして追跡されない場合があります。trainable=Falseの重みは通常のオプティマイザ更新の対象外ですが、状態更新や保存の対象になり得ます。

コード17.2　独自の全結合層
@keras.saving.register_keras_serializable(package="Study")
class Affine(keras.layers.Layer):
    def __init__(self, units, **kwargs):
        super().__init__(**kwargs)
        self.units = units

    def build(self, input_shape):
        self.W = self.add_weight(name="kernel", shape=(input_shape[-1], self.units),
                                 initializer="glorot_uniform", trainable=True)
        self.b = self.add_weight(name="bias", shape=(self.units,), initializer="zeros")
        super().build(input_shape)

    def call(self, inputs):
        return tf.matmul(inputs, self.W) + self.b

    def get_config(self):
        return {**super().get_config(), "units": self.units}

layer = Affine(3)
x = tf.ones((4, 2))
with tf.GradientTape() as tape:
    y = layer(x)
    loss = tf.reduce_sum(y)
gw, gb = tape.gradient(loss, layer.trainable_variables)
assert y.shape == (4, 3)
np.testing.assert_allclose(gw.numpy(), np.full((2, 3), 4.))
np.testing.assert_allclose(gb.numpy(), np.full(3, 4.))

重みをcallのたびに作ると、前回の学習結果が失われるうえ、グラフ実行の制約にも抵触します。入力shapeが決まった最初の呼び出しで作り、その後は再利用します。上の勾配は入力がすべて1なので各要素が4になると手計算できます。

17.3 カスタム活性化関数と補助損失

状態のない演算は関数で実装できます。たとえば固定係数のLeaky ReLUは $g(z)=\max(z,0)+0.1\min(z,0)$ です。一方、係数を学習したい場合はLayerの重みとして持たせます。KerasTensorをFunctional APIで扱う際、TensorFlow演算はカスタムLayerのcall内に置くかkeras.opsを使います。

レイヤーの出力に制約を加えたい場合はadd_lossが利用できます。たとえば中間表現 $a$ の大きさを抑制する補助項 $\lambda\operatorname{mean}(a^2)$ を設定します。標準fitではこの項も目的関数に含まれます。独自ループではmodel.lossesを明示的に加えます。

コード17.3　活性化関数と補助損失を持つ層
@keras.saving.register_keras_serializable(package="Study")
def leaky01(x):
    return keras.ops.maximum(x, 0.) + 0.1 * keras.ops.minimum(x, 0.)

@keras.saving.register_keras_serializable(package="Study")
class ActivityPenalty(keras.layers.Layer):
    def __init__(self, rate=0.001, **kwargs):
        super().__init__(**kwargs)
        self.rate = rate

    def call(self, inputs):
        self.add_loss(self.rate * tf.reduce_mean(tf.square(inputs)))
        return inputs

    def get_config(self):
        return {**super().get_config(), "rate": self.rate}

penalty = ActivityPenalty(rate=0.1)
_ = penalty(tf.constant([[1., 3.]]))
np.testing.assert_allclose(float(penalty.losses[0]), 0.5)

この例は訓練・評価の両方で補助項を加えます。training引数を使う設計では訓練時だけの処理と推論時の処理を区別します。DropoutやBatch Normalizationを含むモデルでは、独自ループでもtraining=True/Falseを正しく渡します。

17.4 カスタム損失関数とサンプル重み

第10章のHuber Lossを独自実装します。残差 $e=\hat y-y$ に対し、閾値 $\delta>0$ を境に二乗と線形を切り替えます。

$$\ell_\delta(e)=\begin{cases}e^2/2 & |e|\le\delta\\\delta(|e|-\delta/2)& |e|>\delta\end{cases}$$

Loss.callは原則として標本ごとの損失を返し、バッチの平均化はLoss基底クラスに委ねます。ここでは回帰の正解・予測をともに(B,D)に統一し、出力軸だけ平均します。マスク付き系列などでは集約軸をタスクに合わせて設計します。

コード17.4　Huber Lossの独自実装と標準実装との照合
@keras.saving.register_keras_serializable(package="Study")
class CustomHuber(keras.losses.Loss):
    def __init__(self, delta=1., **kwargs):
        super().__init__(**kwargs)
        if delta <= 0:
            raise ValueError("delta must be positive")
        self.delta = delta

    def call(self, y_true, y_pred):
        tf.debugging.assert_equal(tf.shape(y_true), tf.shape(y_pred))
        e = tf.abs(y_pred - y_true)
        q = tf.minimum(e, self.delta)
        return tf.reduce_mean(0.5 * q**2 + self.delta * (e-q), axis=-1)

    def get_config(self):
        return {**super().get_config(), "delta": self.delta}

a = tf.zeros((3, 1)); b = tf.constant([[0.5], [2.], [-3.]])
w = tf.constant([1., 2., 0.])
custom = CustomHuber(reduction="none")
np.testing.assert_allclose(custom(a,b), keras.losses.Huber(reduction="none")(a,b))
print(CustomHuber()(a,b,sample_weight=w).numpy())  # 3.125 / 3
print(CustomHuber(reduction="mean_with_sample_weight")(a,b,sample_weight=w).numpy())

17.5 カスタム評価指標と状態の管理

評価指標は必ずしも微分可能である必要はありません。たとえば許容誤差 $\tau$ 以内に予測できた割合を計測する指標を作ります。バッチごとの割合を単純平均すると、端数バッチに含まれる各標本の寄与が過大になります。正しい集約は分子と分母をそれぞれ累積することです。

$$M=\frac{\sum_i w_i\mathbf{1}(|y_i-\hat y_i|\le\tau)}{\sum_i w_i}$$

Metricはupdate_stateで状態を更新し、resultで値を返し、reset_stateで状態を初期化します。以下は単一出力回帰(B,1)専用の例です。sample_weightは(B,)とします。

コード17.5　許容誤差内の割合を集計するMetric
@keras.saving.register_keras_serializable(package="Study")
class WithinTolerance(keras.metrics.Metric):
    def __init__(self, tolerance=0.2, name="within_tolerance", **kwargs):
        super().__init__(name=name, **kwargs)
        if tolerance < 0:
            raise ValueError("tolerance must be nonnegative")
        self.tolerance = tolerance
        self.hits = self.add_weight(name="hits", initializer="zeros")
        self.total = self.add_weight(name="total", initializer="zeros")

    def update_state(self, y_true, y_pred, sample_weight=None):
        y_true = tf.cast(y_true, self.dtype)
        y_pred = tf.cast(y_pred, self.dtype)
        tf.debugging.assert_shapes([(y_true, ("B", 1)), (y_pred, ("B", 1))])
        ok = tf.cast(tf.abs(y_pred[:, 0]-y_true[:, 0]) <= self.tolerance, self.dtype)
        weight = tf.ones_like(ok) if sample_weight is None else tf.cast(tf.reshape(sample_weight, [-1]), self.dtype)
        weight = tf.broadcast_to(weight, tf.shape(ok))
        self.hits.assign_add(tf.reduce_sum(ok * weight))
        self.total.assign_add(tf.reduce_sum(weight))

    def result(self):
        return tf.math.divide_no_nan(self.hits, self.total)

    def reset_state(self):
        self.hits.assign(0.)
        self.total.assign(0.)

    def get_config(self):
        return {**super().get_config(), "tolerance": self.tolerance}

metric = WithinTolerance()
metric.update_state(tf.zeros((4,1)), tf.zeros((4,1)))
metric.update_state(tf.zeros((1,1)), tf.ones((1,1)))
np.testing.assert_allclose(metric.result(), 0.8)
metric.reset_state()

バッチ平均の平均は(1+0)/2=0.5となり、正しい0.8とは異なります（全標本の重みが等しい場合）。compileのmetricsに渡した指標には通常sample_weightが適用されません。重み付き評価が必要ならweighted_metricsに指定します。F1やRMSEも全体の十分統計量から計算する必要があります。AUCのような指標は組み込み実装や全予測による評価を利用します。

17.6 カスタムコールバック

Callbackは学習のイベントを受け取る仕組みです。on_train_begin、on_epoch_begin、on_train_batch_end、on_epoch_end、on_train_endなどを利用します。logsには利用可能な損失や評価指標が入ります。検証データを使う処理では、検証が実施されないエポックに備えてキーの存在を確認します。

コード17.6　検証指標の改善を記録するCallback
class ImprovementLog(keras.callbacks.Callback):
    def on_train_begin(self, logs=None):
        self.best = float("inf")
        self.records = []

    def on_epoch_end(self, epoch, logs=None):
        value = (logs or {}).get("val_loss")
        if value is not None and np.isfinite(value) and value < self.best:
            self.best = float(value)
            self.records.append((epoch+1, self.best))
            print(f"epoch={epoch+1}: best val_loss={self.best:.5f}")

コールバックを用いて検証指標を追加しModelCheckpointで監視する場合、指標をlogsに追加するコールバックを先に配置します。毎バッチのPython処理は速度低下の原因になります。テスト集合を使ったモデル選択は行わないようにしましょう。

17.7 train_stepとtest_stepのオーバーライド

標準fitのエポック管理やCallbacksを維持しつつ、1バッチの更新処理だけを変更できます。ここではグローバルノルムによる勾配クリッピングを例にします。勾配全体のノルム $G=\sqrt{\sum_j\|g_j\|^2}$ が上限 $c$ を超えるとき、全勾配に $c/G$ を掛けます。上限は正の値とします。通常はOptimizerのglobal_clipnormでも実現できますが、学習ステップの構造を理解するため手書きします。

コード17.7　独自の学習・評価ステップ
@keras.saving.register_keras_serializable(package="Study")
class ClippedRegressor(keras.Model):
    def __init__(self, width=16, clip_norm=1., **kwargs):
        super().__init__(**kwargs)
        self.width = width
        if clip_norm <= 0:
            raise ValueError("clip_norm must be positive")
        self.clip_norm = clip_norm
        self.hidden = Affine(width)
        self.penalty = ActivityPenalty()
        self.head = Affine(1)
        self.loss_meter = keras.metrics.Mean(name="loss")
        self.score = WithinTolerance()

    def call(self, x, training=False):
        return self.head(self.penalty(leaky01(self.hidden(x))))

    @property
    def metrics(self):
        return [self.loss_meter, self.score]

    def train_step(self, data):
        x, y, sw = keras.utils.unpack_x_y_sample_weight(data)
        with tf.GradientTape() as tape:
            pred = self(x, training=True)
            loss = self.compute_loss(x=x, y=y, y_pred=pred, sample_weight=sw)
        variables = self.trainable_variables
        grads = tape.gradient(loss, variables)
        if any(g is None for g in grads):
            raise ValueError("Disconnected gradient")
        for g in grads:
            tf.debugging.assert_all_finite(g, "Invalid gradient")
        grads, _ = tf.clip_by_global_norm(grads, self.clip_norm)
        self.optimizer.apply_gradients(zip(grads, variables))
        return self.record(y, pred, loss, sw)

    def test_step(self, data):
        x, y, sw = keras.utils.unpack_x_y_sample_weight(data)
        pred = self(x, training=False)
        loss = self.compute_loss(x=x, y=y, y_pred=pred, sample_weight=sw)
        return self.record(y, pred, loss, sw)

    def record(self, y, pred, loss, sw):
        self.loss_meter.update_state(loss, sample_weight=tf.shape(y)[0])
        self.score.update_state(y, pred, sample_weight=sw)
        return {m.name: m.result() for m in self.metrics}

    def get_config(self):
        return {**super().get_config(), "width": self.width, "clip_norm": self.clip_norm}

compute_lossはcompileで設定された損失とmodel.lossesを含みます。この例の集約はsum_over_batch_sizeの損失を前提に標本数で重み付けしています。mean_with_sample_weightの場合は、損失の分母と補助項を別々に集計するなど設計を変更します。metricsプロパティに列挙した指標はfit/evaluateによってリセットされます。本例はcompileにmetricsを渡さず、独自指標を明示管理します。混合精度・分散学習は本例の対象外です。

17.8 Custom Training Loop：学習全体を制御する

複数回の更新、独自のエポック定義、複数のモデルの交互学習などでは、ループ全体を管理する方法が有用です。以下では標準の回帰モデルを独自ループで学習します。訓練と検証でMetricを分け、更新前の予測で訓練指標を記録します。検証では更新を行いません。

コード17.8　データ準備と独自ループ
rng = np.random.default_rng(42)
X = rng.uniform(-2, 2, (640, 1)).astype("float32")
y = (np.sin(2*X) + rng.normal(0, .05, X.shape)).astype("float32")
idx = rng.permutation(len(X))
tr, va, te = idx[:400], idx[400:520], idx[520:]
train_ds = tf.data.Dataset.from_tensor_slices((X[tr], y[tr])).shuffle(len(tr), seed=42).batch(32).prefetch(tf.data.AUTOTUNE)
val_ds = tf.data.Dataset.from_tensor_slices((X[va], y[va])).batch(32)
net = keras.Sequential([keras.Input((1,)), Affine(16), keras.layers.Activation(leaky01), ActivityPenalty(), Affine(1)])
opt = keras.optimizers.Adam(.01)
loss_fn = CustomHuber()
train_mae = keras.metrics.MeanAbsoluteError()
val_mae = keras.metrics.MeanAbsoluteError()

@tf.function
def step(xb, yb):
    with tf.GradientTape() as tape:
        pred = net(xb, training=True)
        loss = loss_fn(yb, pred)
        if net.losses:
            loss += tf.add_n(net.losses)
    grads = tape.gradient(loss, net.trainable_variables)
    opt.apply_gradients(zip(grads, net.trainable_variables))
    train_mae.update_state(yb, pred)

history = {"train": [], "val": []}
for epoch in range(30):
    train_mae.reset_state(); val_mae.reset_state()
    for xb, yb in train_ds:
        step(xb, yb)
    for xb, yb in val_ds:
        val_mae.update_state(yb, net(xb, training=False))
    history["train"].append(float(train_mae.result()))
    history["val"].append(float(val_mae.result()))
plt.plot(range(1, len(history["train"])+1), history["train"], label="train MAE")
plt.plot(range(1, len(history["val"])+1), history["val"], label="validation MAE")
plt.xlabel("epoch"); plt.legend(); plt.show()

独自ループではEarlyStoppingやModelCheckpointは自動では呼ばれません。必要ならCallbackListを正しく構成するか、終了判定・保存処理を実装します。tf.functionの外でPythonの履歴を更新し、最初はEagerで動作確認してからグラフ化するとデバッグしやすくなります。

17.9 シリアライズとモデルの保存・復元

独自クラスを含むモデルを保存するには、設定と状態の違いを理解する必要があります。get_configはコンストラクタに渡す設定を辞書として返し、add_weightによる状態は別途保存されます。register_keras_serializableにより登録名でオブジェクトを復元できます。ただし.kerasファイルにはPythonのクラス定義そのものは含まれません。別プロセスでは定義したモジュールを先にimportします。

コード17.9　保存と予測値の照合
model = ClippedRegressor(width=16, clip_norm=1.)
_ = model(tf.zeros((1,1)))
model.compile(optimizer=keras.optimizers.Adam(.01), loss=CustomHuber())
log = ImprovementLog()
h = model.fit(train_ds, validation_data=val_ds, epochs=40, verbose=0,
              callbacks=[log, keras.callbacks.EarlyStopping(patience=6, restore_best_weights=True)])
model.save("custom_regressor.keras")
restored = keras.models.load_model("custom_regressor.keras")
np.testing.assert_allclose(model(X[va], training=False), restored(X[va], training=False), rtol=1e-5, atol=1e-6)
print(restored.evaluate(X[te], y[te], return_dict=True, verbose=0))

学習再開時にはオプティマイザの状態も確認します。EarlyStoppingで重みを戻した場合、オプティマイザの状態が同じ時点に戻るとは限りません。最良エポックから再開する目的なら、その時点のモデル全体をModelCheckpointで保存します。信頼できないファイルの読み込みには注意し、安易にsafe_mode=Falseを指定しないでください。

17.10 実践：比較実験とデバッグ

上記の独自モデルと同じ構成を持つ標準モデルで、クリッピングの有無を比較します。訓練・検証分割と初期重み、データ順序、損失関数をそろえ、検証MAEを共通指標にします。下のコードでは比較のためシャッフルなしの固定順序を用います。テスト集合は設定を選び終えた後にのみ使用します。

コード17.10　クリッピングの有無を比較する
def make_standard():
    return keras.Sequential([keras.Input((1,)), Affine(16),
        keras.layers.Activation(leaky01), ActivityPenalty(), Affine(1)])
base = make_standard()
initial = base.get_weights()
results = {}
for label, clip in [("no clipping", None), ("clipping", 1.)]:
    m = make_standard()
    m.set_weights(initial)
    m.compile(optimizer=keras.optimizers.Adam(.01, global_clipnorm=clip),
              loss=CustomHuber(), metrics=[keras.metrics.MeanAbsoluteError()])
    hist = m.fit(X[tr], y[tr], validation_data=(X[va], y[va]),
                 batch_size=32, epochs=40, shuffle=False, verbose=0)
    results[label] = hist.history["val_mean_absolute_error"]
for label, values in results.items():
    plt.plot(range(1, len(values)+1), values, label=label)
plt.xlabel("epoch"); plt.ylabel("validation MAE"); plt.legend(); plt.show()

クリッピングが有効であるかは勾配ノルムや検証結果によって判断します。上限が小さすぎれば学習が遅くなり得ます。ここでは組み込みOptimizerで比較し、独自train_stepの必要性と標準機能による代替可能性を区別しています。実測の学習曲線は未掲載です。

17.11 まとめと確認問題

標準の機能で解けるなら標準を利用し、必要な箇所だけを拡張します。独自処理では数式とshape、勾配、集約、学習と推論の違い、保存後の再現性を個別に検証することが大切です。

問　buildとcallの違いは？

buildは入力形状に依存する状態を作り、callは繰り返し実行する計算を定義する。

問　Loss.callでバッチ平均を避ける理由は？

標本重みやreductionを基底クラスが処理できるよう、標本ごとの損失を返す。

問　4件中4件、1件中0件が正解なら全体の正解率は？

4/5=0.8。バッチ平均の単純平均0.5は誤り。

問　add_lossは独自ループで自動的に加算されるか？

されない。model.lossesを目的関数に加える。compute_lossを利用する場合は重複加算しない。

問　test_stepでOptimizerを呼ぶべきか？

呼ばない。検証・評価時はパラメータを更新しない。

問　勾配(3,4)を上限2でクリップすると？

ノルム5なので倍率0.4、(1.2,1.6)となる。

問　カスタムクラスを別のPythonプロセスで復元する条件は？

定義をimportし登録名を解決できること。設定から再構築できること。

問　独自ループでCallbacksが自動で動くか？

動かない。必要なイベント呼び出しや同等の制御を実装する。

発展演習：勾配クリッピングを検証する

二つの勾配テンソル[3,4]と[12]をまとめて上限6.5でクリップします。個別のノルムでクリップする場合と比較し、方向が維持されることを確認してください。

解答・実装例
コード17.11　グローバルノルムの数値検証
g = [tf.constant([3.,4.]), tf.constant([12.])]
clipped, norm = tf.clip_by_global_norm(g, 6.5)
np.testing.assert_allclose(norm.numpy(), 13.)
np.testing.assert_allclose(clipped[0], [1.5,2.])
np.testing.assert_allclose(clipped[1], [6.])
np.testing.assert_allclose(tf.linalg.global_norm(clipped), 6.5)
individual = [tf.clip_by_norm(v, 6.5) for v in g]
print(tf.linalg.global_norm(individual).numpy())  # 約8.20061。全体の方向は変化する
